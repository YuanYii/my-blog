## 一、跨角色通用问题

### 1. 日期计算方式不明确

**问题**：多个角色要求 `SRC = RUN - 1 天`，但未说明具体怎么算。

涉及角色：
- 02_开发工程师.md：`SRC = RUN - 1 天`
- 04_测试工程师.md：`SRC = RUN - 1 天`
- 06_项目经理.md：`SRC = RUN - 1 天`
- 07_文档工程师.md：`SRC = RUN - 1 天`

**风险**：若 RUN=20260301（3月1日），`RUN-1` 作为整数减法 = 20260299（非法日期），或作为字符串截断都不正确。

**建议**：统一加上日期计算命令：
```bash
# 正确方式
SRC=$(date -v-1d -j -f "%Y%m%d" "20260603" "+%Y%m%d" 2>/dev/null || date -d "20260603 -1 day" "+%Y%m%d")
```

**优化优先级**：🔴 高（可能导致选错文件，整个流水线处理错误日期的数据）

### 2. 输出目录可能不存在

**问题**：以下角色写入文件时，未检查目标目录是否存在：
- 03_代码质量审查员.md → `audit_code/{RUN}_codereview_v1.md`（目录可能不存在）
- 04_测试工程师.md → `audit_code/{RUN}_audit_vN.md`（同上）
- 05_集成测试员.md → `audit_code/{RUN}_integration_v1.md`（同上）
- 08_发布管理员.md → `autodev/auto_iteration/{RUN}_release.md`（目录应存在，但未确认）

**建议**：在每个角色的「处理流程」→「输出报告」步骤前，加一句：
> 若输出目录不存在，先执行 `mkdir -p <目录>` 创建。

**优化优先级**：🟡 中（首次运行必报错）

**问题**：

### 4. `RUN` / `SRC` 定义重复且可能冲突

**问题**：每个角色都在开头重复定义 `RUN` 和 `SRC`，但定义文字不完全一致。

对比：
- 03_代码质量审查员.md：`SRC = RUN`（审查当天，与开发工程师同日）
- 05_集成测试员.md：`SRC = RUN`（集成测试与测试工程师同一天）
- 其他角色：`SRC = RUN - 1 天`

**建议**：
1. 在 `autodev/README.md` 中统一定义 `RUN` / `SRC` 及各角色的对应关系
2. 各角色提示词开头改为引用：「日期变量定义见 `../README.md §关键约定」

**优化优先级**：🟡 中（目前实际运行没问题，但维护成本高）

## 四、优化建议总结

### 建议 1：统一日期计算函数

在 `autodev/README.md` 中增加：

```markdown
### 日期计算（所有角色共用）

不要对 YYYYMMDD 格式做整数减法（跨月/跨年错误）。

正确方式（macOS）：
```bash
date -v-1d -j -f "%Y%m%d" "20260603" "+%Y%m%d"
# 输出：20260602
```

正确方式（Linux）：
```bash
date -d "20260603 -1 day" "+%Y%m%d"
# 输出：20260602
```

跨平台兼容写法（推荐）：
```bash
# 用 Python 算（macOS / Linux 都可用）
python3 -c "from datetime import datetime, timedelta; print((datetime.strptime('20260603', '%Y%m%d') - timedelta(days=1)).strftime('%Y%m%d'))"
```
```
