## 审查维度

### 1. 代码规范（Style）

依据：`{{DOC_AGENTS}}` 中的项目约定 + Sun/Oracle Java 编码规范 + {{TECH_FRONTEND}} / TypeScript 社区规范

检查项：
- 命名规范（类/方法/变量/常量）
- 注释完整性（公共方法是否有 Javadoc/JSDoc）
- 文件长度（Java 文件 > 500 行标警告，Vue SFC > 300 行标警告，{{TECH_BACKEND}} Controller/Service 可适当放宽）
- 方法长度（Java 方法 > 80 行标警告，Vue SFC 方法 > 50 行标警告）
- 重复代码（相同逻辑出现 2 次以上标警告）

### 2. 性能（Performance）

检查项：
- **N+1 查询**：循环中执行数据库查询（{{TECH_ORM}} `selectById` 在循环里）
- **未分页大查询**：`selectList` 无 `Wrapper.limit()` 或 `Page` 分页
- **资源未关闭**：`InputStream` / `OutputStream` / `Connection` 无 try-with-resources
- **大对象持有**：方法内持有大字符串/大集合超过必要范围
- **Redis N+1**：循环中逐条 `redisTemplate.opsForValue().get()`（应 pipeline 或 mget）
- **前端大 bundle**：`node_modules` 中包被全量引入（如 lodash 全量 import）

### 3. 安全（Security）

检查项：
- **SQL 注入**：字符串拼接 SQL（非 {{TECH_ORM}} `Wrapper` 构造）
- **XSS**：用户输入直接 `v-html` 或 `innerHTML`，无转义
- **敏感信息泄露**：日志中打印 `password` / `token` / `passwordHash`（见 `AGENTS.md` §4.9 安全红线 禁打字段；若 `AGENTS.md` 不存在或无 §4.9，使用内置默认列表：password/token/secret/key/private/apiKey）
- **JWT secret 硬编码**：代码中直接写死 secret 字符串
- **未鉴权接口**：`{{MODULE_APP}}` 模块中新增接口无 `@RequiresPermissions` 或等价鉴权
- **CORS 通配**：`allowed-origins: "*"` 在生产环境

### 3.1 前端专项安全检查（{{TECH_FRONTEND}}）
检查项：
- **`useFetch` / `$fetch` 未做错误处理**：调用后无 `.catch()` 或 `try/catch`，导致 SSR 崩溃时无错误边界
- **`process.env` / `useRuntimeConfig()` 泄露到客户端**：敏感配置（如 JWT secret、数据库密码）出现在客户端 bundle 中（检查 `nuxt.config.ts` 的 `runtimeConfig` 配置）
- **middleware 鉴权遗漏**：`middleware/auth.ts` 未覆盖新增的 admin 页面路由
- **`v-html` 未做 sanitize**：用户输入直接渲染 HTML，无 DOMPurify 等 sanitize 处理
- **前端路由鉴权绕过**：新增页面未在 `middleware/admin-auth.ts` 中注册鉴权

## 异常处理

| 情况 | 处理方式 |
|------|----------|
| `{SRC}.md` 不存在 | 结束，回复"无追踪文档，跳过代码质量审查" |
| 无 ✅ 已完成任务 | 输出空报告（汇总全 0），回复"无已完成任务，无需审查" |
| 涉及文件不存在 | 在报告中标注"文件未找到"，继续审查其余文件 |
| 文件内容过长（>1000 行） | 标注"文件过长，仅审查关键方法"，列出已审查的方法名 |
