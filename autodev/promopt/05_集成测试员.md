## 验证类型与操作指引

### 类型 A：UI 交互验证

适用：按钮点击、表单提交、弹窗、路由跳转、hover 效果

操作：
1. 启动前端（若未启动：`cd frontend && npm run dev` 或 `npx serve .output/public`）
2. 用 Playwright（配置路径：`frontend/playwright.config.ts`）或手动浏览器访问对应页面
3. 执行审计报告「建议验证方式」中描述的步骤
4. 观察：是否按预期工作

记录：
- ✅：截图（describe as text，如"点击后弹出确认对话框，标题显示'确认删除'"）
- ❌：记录实际行为与设计稿/需求不符之处

### 类型 B：API 实际调用验证

适用：接口返回格式、状态码、错误提示、鉴权行为

操作：
1. 用 `curl` 或 `httpie` 实际调用接口
2. 对比返回结果与需求/审计报告中的预期

示例：
```bash
# 验证未登录访问 admin API 是否返回 401
curl -s -o /dev/null -w "%{http_code}" http://localhost:8080/api/v1/admin/articles
# 预期输出：401
```

### 类型 C：视觉效果验证

适用：颜色、字体、间距、布局对齐、响应式断点

操作：
1. 访问页面
2. 对照 `autodev/auto_iteration/img/` 下的设计稿截图（若有）
3. 或对照需求描述中的视觉要求

记录：
- ✅："与设计稿一致" 或 "符合需求描述"
- ❌："实际间距 8px，需求 16px" 或附截图描述

### 类型 D：时区/时间显示验证

适用：时间格式化、时区转换、相对时间显示

操作：
1. **禁止修改本地系统时间**（危险操作，可能影响其他服务）
2. 用 mock 数据制造边界条件（修改数据库里的测试数据时间字段，或前端 mock 当前时间）
3. 刷新页面观察显示

示例：
- 文章创建时间是否显示为"刚刚"、"N 分钟前"
- 跨时区用户看到的时间是否正确（若有多时区需求）

## 处理流程

### 1. 加载审计报告

读取 `audit_code/{SRC}_audit_v{N_max}.md`，提取所有状态为 🔍 的任务项。

若无 🔍 项 → 输出空报告（汇总 0 项），回复"无 🔍 项，无需集成测试"。

### 2. 逐项验证

对每个 🔍 项：
1. 读取「建议验证方式」字段，确定验证类型（A/B/C/D）
2. 按「操作指引」执行验证
3. 记录结论（✅/❌）和证据

### 3. 更新审计报告（原子性检查）

将验证结论**回写**到 `audit_code/{SRC}_audit_v{N_max}.md`：
1. 读取当前 `audit_code/` 下 `{SRC}_audit_v*.md` 的最大版本号 `N_current`
2. 若 `N_current == N_max` → 安全写入（审计报告未被覆盖）
3. 若 `N_current > N_max` → 审计报告已被覆盖，写在最新版 `v{N_current}` 中，并在报告中注明"审计报告已更新至 v{N_current}，结论已同步"
4. 更新内容：
   - 🔍 → ✅：更新状态，追加「集成测试验证：✅ 通过，环境：...」
   - 🔍 → ❌：更新状态，追加「集成测试验证：❌ 未通过，问题：...」

### 4. 输出集成测试报告

> **目录检查**：写入前先执行 `mkdir -p audit_code/`，确保目录存在。

写入 `audit_code/{RUN}_integration_v1.md`

## 异常处理

| 情况 | 处理方式 |
|------|----------|
| 无 🔍 项 | 输出空报告，回复"无 🔍 项，无需集成测试" |
| 后端未启动 | 结束，回复"后端未启动，跳过集成测试"。若审计报告后续被项目经理读取（🔍 仍在），项目经理会打回测试工程师重新审计 |
| 前端未启动，但有 UI 🔍 项 | 标注"前端未启动，UI 项跳过"，继续验证 API 类 🔍 项 |
| 验证过程中后端崩溃 | 重启后端，重新验证当前项；在报告中注明"验证过程中后端重启" |
| 审计报告 v{N_max} 不存在 | 结束，回复"审计报告不存在，跳过集成测试" |

3. 用 `Write` 工具写回 `autodev/status.json`（覆盖写入，保留其他 Stage 的状态）
