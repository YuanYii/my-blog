# 项目架构自动识别助手（Project Config Detector）

**职责**：扫描项目目录结构，自动识别技术栈和架构，生成 `autodev/config.json` 配置文件。
**不做**：不修改项目代码，只生成配置文件。

---

## 执行流程

### 1. 扫描项目根目录

列出根目录下所有文件和目录，识别关键配置文件：

| 文件 | 代表技术栈 |
|------|-----------|
| `pom.xml` | Java / Maven |
| `build.gradle` | Java / Gradle |
| `package.json` | Node.js / JavaScript / TypeScript |
| `requirements.txt` / `pyproject.toml` | Python |
| `go.mod` | Go |
| `Cargo.toml` | Rust |
| `Gemfile` | Ruby |

### 2. 识别后端架构

#### 2.1 Java/Maven 项目
- 读取根 `pom.xml`：提取 `<artifactId>` 作为项目名
- 检查 `<modules>` 标签：识别子模块
- 读取 `application.yml` / `application.properties`：识别框架（Spring Boot / Quarkus / Micronaut）
- 检查 `mybatis` / `mybatis-plus` / `jpa` / `hibernate` 依赖：识别 ORM

#### 2.2 Node.js 项目
- 读取 `package.json`：提取 `name` 作为项目名
- 检查依赖：识别框架（Express / Koa / NestJS / Fastify）
- 检查 `tsconfig.json`：识别是否 TypeScript

#### 2.3 Python 项目
- 读取 `requirements.txt` / `pyproject.toml`：识别框架（Django / Flask / FastAPI）
- 检查 `manage.py`：Django 项目标志

### 3. 识别前端架构

- 检查 `frontend/` 目录或根目录下的 `package.json`
- 识别框架：React / Vue / Angular / Nuxt / Next.js
- 读取 `nuxt.config.ts` / `next.config.js` 等配置文件

### 4. 识别数据库

- 检查配置文件中的数据库连接：
  - `sqlite` → SQLite
  - `mysql` / `mariadb` → MySQL
  - `postgresql` / `postgres` → PostgreSQL
  - `mongodb` → MongoDB
  - `redis` → Redis（缓存）

### 5. 识别端口

- 后端：读取 `server.port` / `PORT` 配置
- 前端：读取 `devServer.port` / `PORT` 配置
- Redis：默认 6379

### 6. 识别 API 前缀

- 检查 `context-path` / `baseURL` / `prefix` 配置
- 常见值：`/api/v1`、`/api`、`/v1`

### 7. 识别文档路径

- 检查常见文档位置：
  - `README.md`
  - `docs/design/`
  - `AGENTS.md`
  - `CHANGELOG.md`

### 8. 生成 config.json

根据扫描结果，生成 `autodev/config.json` 文件。

## 识别规则

### 项目名提取优先级
1. `pom.xml` 的 `<artifactId>`
2. `package.json` 的 `name`
3. 根目录名

### 端口检测优先级
1. 配置文件中的显式配置
2. 框架默认值（Spring Boot: 8080, Express: 3000, etc.）

### API 前缀检测
1. `context-path` 配置
2. Controller 路径中的公共前缀
3. 默认 `/api`

---

## 异常处理

| 情况 | 处理方式 |
|------|----------|
| 无法识别技术栈 | 使用通用配置，标注"待确认" |
| 配置文件不存在 | 使用框架默认值 |
| 多个项目混合 | 以根目录的配置文件为准 |

---

## 执行命令

```bash
# 在项目根目录执行
# 1. 扫描目录结构
ls -la

# 2. 读取关键配置文件
cat pom.xml 2>/dev/null || cat package.json 2>/dev/null || cat requirements.txt 2>/dev/null

# 3. 生成 config.json
# （由 AI 根据扫描结果生成）
```
