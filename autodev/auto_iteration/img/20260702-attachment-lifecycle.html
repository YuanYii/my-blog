7 个关键决策点 DECISION

2026-07-01 DEV-001 整套体系 —— 决策点都围绕"一文一附件 + 二段删除 + 路径安全 + 跨方言 UNIQUE 兜底"

并发竞态
D-1 · 一文一附件 + UNIQUE + try-insert 兜底
article_id 字段加 UNIQUE 约束（DB 层兜底）。两个 POST 同时通过 selectCount 都 INSERT，第二个撞 UNIQUE。修法：try-insert + catch UNIQUE 异常，删落盘文件兜底 + 返 400 "请先删除旧附件"。跨方言一致：catch 递归查 cause 链找 UNIQUE constraint failed / SQLITE_CONSTRAINT_UNIQUE。
2026-07-01 DEV-001 fix
生命周期
D-2 · 二段删除（软删文件保留 vs 硬删先文件后 DB）
软删：UPDATE deleted=1，磁盘文件保留——给"误删后悔"留缓冲期，公开页展示"已删除"提示。硬删：先删文件再删 DB——删 DB 后无法定位文件路径；删文件失败抛 500 阻断后续。文件不存在容错：可能上次硬删文件成功但 DB 失败留下的孤儿记录。
2026-07-01 DEV-001
路径安全
D-3 · resolveFile 防路径穿越（normalize + startsWith）
resolveFile(a) 用 Paths.get(attachmentDir).resolve(a.getFilePath()).normalize() 标准化，resolved 必须 startsWith attachmentDir，否则 ERROR log + 抛 400 "附件路径非法"。防攻击者上传 filePath=../../../etc/passwd 之类的恶意 DB 记录逃逸 attachment 根目录。
AttachmentService L424
MP 兼容
D-4 · restore JdbcTemplate 直 UPDATE 绕过 logic-delete
原 attachmentMapper.update(null, uw) 走 MyBatis-Plus 全局 logic-delete 自动加 AND deleted=0，restore 是 1→0 转换 WHERE 永远不匹配 → API 返 200 但 DB 实际 0 行更新。修：所有 UPDATE / 涉及 deleted 字段的 SELECT 都改 JdbcTemplate 直查直改。
2026-07-01 二次修复
性能 · 大文件
D-5 · 流式下载 InputStreamResource（避 OOM）
公开下载用 InputStreamResource(new FileInputStream(p)) + StreamUtils.copy 流式响应，不读 byte[]。如果用 Files.readAllBytes 单文件 5MB × 高并发直接 OOM。Spring MVC 直接消费 ResponseEntity body 流，大文件友好。
AttachmentController L77
数据契约
D-6 · 后台列表 LEFT JOIN article（避免 N+1）
list() 一条 SQL FROM article_attachment att LEFT JOIN article a 同时取 articleTitle / articleDeleted。避免 N+1（N 篇文章各查一次）。前端 attachments.vue 用这两个字段："关联文章"列 + 已删除文章对应附件的"恢复/查看文章"按钮控制。孤儿附件（article 不存在）articleDeleted 兜底为 1，按"已删除"显示。
2026-07-01 OPT-002/003
跨方言
D-7 · UNIQUE 冲突 catch 递归查 cause 链
SQLite JDBC 抛原生 SQLiteException（SQL state null，error code 19）→ Spring SQLExceptionTranslator 因 SQLite 错误码不在内置 mapping 里，包成 UncategorizedSQLException 而不是 DataIntegrityViolationException。修法：catch (Exception e) 递归查 cause 链 message 含 UNIQUE constraint failed / SQLITE_CONSTRAINT_UNIQUE。真异常靠非 UNIQUE 错误码或完全不同 message 区分。
2026-07-01 DEV-001 fix
