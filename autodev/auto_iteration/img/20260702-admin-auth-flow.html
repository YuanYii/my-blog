My-Blog · Admin Auth · End-to-end Pipeline

博客 admin 鉴权链路业务逻辑图

梳理任意 HTTP 请求进入 Spring 过滤链 → AdminAuthFilter.shouldNotFilter 路径分流 → doFilterInternal 三段鉴权（token / 设备 / token-deviceId 对账）→ AOP 审计日志自动落库的完整链。适用版本：v5.0.0+。

主流程 · admin 鉴权端到端链路 FLOW

2 大阶段：阶段 A 路径分流（shouldNotFilter 决定鉴权/放行/拒绝）→ 阶段 B 三段鉴权（token / 设备白名单 / token-deviceId 一致性）。任一段失败立即返回 401 并打 WARN；AOP 在 controller 完成后异步写 audit_log。

8 个关键决策点 DECISION

每个决策都源自一个具体历史 BUG / OPT —— "为什么不写 if-else 短路" 的工程取舍都列在这里

阶段 A · 路径分流
D-1 · ADMIN_ROUTES 显式路由表 + default-deny
不靠"白名单即安全"的默认放行——admin 表显式枚举每个端点，DB public 白名单兜底已公开 GET，其余写操作一律 default-deny。未登记的 GET 防漏 WARN 后放行（防误伤新增公开端点），写操作直接 401 + WARN。代价是新增 admin 端点要登记；好处是不存在"忘了加白名单就被越权"的攻击面。
2026-06-20 B2 重构
阶段 A · 白名单匹配
D-2 · ApiWhitelistService 最长前缀优先
refreshCache() 按 pathPrefix.length() 倒序排 → matchPath() for-loop 第一个命中即最长前缀。防止 /admin(admin) 排在 /admin/public-thing(public) 前面时，公开子路径被误截。路径边界校验（prefix 必须等于 path 本身或下一字符是 /）防 /articles 误匹配 /articlesXXX。
2026-06-12 修复
阶段 B · Token 解析
D-3 · JwtUtil 启动时 secret 强度校验（fail-fast）
@PostConstruct validateSecret() 启动时校验 secret ≥ 32 字节（HS256 安全要求）。原实现不校验，弱 secret 一旦上线签名直接不安全。dev 默认值（65 字节）正常通过；prod 没设 JWT_SECRET env → Spring 占位符解析失败 → 更早 fail-fast。
2026-06-07 安全加固
阶段 B · Token 防借用
D-4 · token.deviceId claim + Header X-Device-Id 双向校验
JwtUtil.generate 时把 deviceId 塞进 claim，AdminAuthFilter 验 token 后比对 header：claim 不一致 → 401。防 token 一旦泄漏被别人拷贝走——别人的浏览器没有原 deviceId，token 即使被偷也是废纸。
REQ-L2-2026-06-07
阶段 B · 设备白名单
D-5 · DeviceService bootstrap 首设备自动 approved
"鸡生蛋"问题：首次部署 / 误清空 admin_device 表 → 没有 approved 设备就无法登录后台 → 无法批准别人。修法：表空时第一个密码通过校验的设备直接 approved（approved_by="system-bootstrap"）。安全前提是密码已通过 BCrypt 校验，bootstrap 只是省 admin 自批自己一次。
2026-06-12 安全加固
阶段 B · 设备白名单
D-6 · trust-migrate 内网限定通道
旧客户端没传 X-Device-Id 时（旧版兼容期）走 trust-migrate 自动建 approved。防止外网任意请求不传 deviceId 就绕过白名单拿 token——trust-migrate 限内网 IP（loopback / RFC 1918 私网 / IPv6 ULA），外部请求 reject 成 DEVICE_PENDING。
2026-06-07 安全加固
阶段 A · 防日志放大
D-7 · warnUnregistered 去重 + IP 频次
攻击者扫各种未登记路径会打爆日志。warnedKeys 集合（同 method:path 进程内只打一次）+ warnRateMap（同 IP 每分钟最多 unregisteredWarnPerMin=5 条）+ @Scheduled 60s 周期清理过期 entry 防内存泄漏。超阈值降 DEBUG，防日志放大攻击。
2026-06-22 v4.x polish
阶段 C · 审计落库
D-8 · AuditLogAspect @Async 异步 + AOP 兜底
切点 execution(* com.blog..controller..*(..)) 包所有 controller method；反射 @PostMapping 等注解拿 HTTP method + path pattern（零字符串拼接）；AuthContext.uid() 存在时才认 admin 写端点。AuditLogService.record() 标 @Async，写库失败仅 WARN，不影响业务返回 200。
