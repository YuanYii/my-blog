后台守护机制 GUARD

3 层守护：DB 唯一索引 → JVM startup reconciler → 5s/60s 定时扫描，回收被强杀进程遗留的孤儿 RUNNING 记录

backup_record
SQLite partial unique index
WHERE status='RUNNING'
单进程并发互斥（第二次 INSERT 直接抛 UNIQUE constraint failed → BusinessException BACKUP_CONFLICT）
restore_record
同款 partial unique index；任一时刻最多 1 条 RUNNING 的备份 / 恢复任务，避免并发写文件相互覆盖
BackupStartupReconciler
@Scheduled：JVM 启动 + 5s 二次 + 60s 周期
扫 RUNNING 备份孤儿 → 读 .blog-backup-result.{id}.json
SUCCESS / FAILED / ORPHAN / RESULT_PARSE_FAILED 四态映射
RestoreStartupReconciler
同款机制，扫 RUNNING 恢复孤儿
合并 .restore-meta.{id}.json + .restore-result.{id}.json
反向 INSERT 重建记录
RESULT 文件反查
脚本侧用 BACKUP_STAGE_DIR_PARENT/.blog-backup-result.{id}.json
携带完整 SUCCESS 字段；result_dir 不被 trap 清理，可被 reconciler 反查
traceId 串联
TraceIdUtil 全链路（AdminAuthFilter / IpRateLimitFilter / GlobalExceptionHandler）
backup_record.trace_id 存当前请求 traceId
失败详情直接展示给 owner 反查 server log

关键文件清单

按链路参与顺序排列：脚本入口 → Java Service → 备份/恢复核心实现

scripts/blog-backup.sh
生产环境定时 + 手动备份入口；调 sqlite-export.sh dump db + 打包 uploads/attachments；上传 GitHub Release；写 backup_record
scripts/sqlite-export.sh
sqlite3 .dump 全表（或按 --exclude 过滤）→ gzip → openssl AES-256-CBC + PBKDF2 10 加密 → 输出 .sql.gz.enc
scripts/sqlite-import.sh
解密 + 解压 + sqlite3 执行 dump.sql；供 INITIAL_DB=1 部署首次初始化用
scripts/publish-release.sh
开发者本地发布入口；EXPORT_DB=1 时调 sqlite-export.sh 把 dev db 加密导出随 Release 发版
scripts/deploy-server.sh
服务器端部署脚本；IMPORT_DB=1 时调 sqlite-import.sh 自动解密导入；DEPLOY_MODE=full/data/code 分流
BackupController.java
admin 后台触发入口：POST /admin/backup/run（异步执行）/ sync（从 GitHub 拉历史）/ delete（删记录）
BackupService.java
@Async 调度 + ProcessBuilder 调 blog-backup.sh + write backup_record + trimOldRecords + .blog-backup-result.{id}.json
RestoreController.java
admin 后台触发入口：POST /admin/restore/run（异步执行） / list / get
RestoreService.java
写 restore_record + .restore-meta.{id}.json；@Async 调度 RestoreExecutor.execute
restore/RestoreExecutor.java
12 步执行：PRECHECK → STOP → DOWNLOAD → SHA256 → DECRYPT → IMPORT → UPLOADS → START → HEALTH → VERIFY → ORPHAN → UPDATE
restore/SqliteOnlineBackup.java
用 SQLite C API（sqlite3_backup_init/step/finish）做在线热备；buildStagedDbFromSql + copyOver 整 db 文件替换
restore/EncryptedDumpCodec.java
openssl 解密 + gunzip 解压的 codec；与 sqlite-export.sh 加密参数对齐
BackupStartupReconciler.java
@Scheduled 启动 + 5s + 60s 扫 RUNNING 备份孤儿；读 .result.json 反查 SUCCESS 字段
RestoreStartupReconciler.java
同款机制，对应恢复任务；按 source_tag 把孤儿 RUNNING 备份修正为 SUCCESS
