### 20260708-DEV-001 | 高 | ✅ 已完成

- **开发内容**：
  宿主机升级代理（upgrade-agent），需求如下：

      1. Python 脚本，监听 127.0.0.1:28081
      2. 接收 POST /upgrade 请求，参数：version（版本号）、mode（full/init）、importDb（是否导入数据）、confirm（确认码）
      3. 调用 deploy-server.sh 执行升级
      4. 通过 SSE 流式返回升级日志
      5. 升级锁：同一时间只允许一个升级任务
      6. systemd 服务文件（upgrade-agent.service）
      7. 安全：仅监听 localhost，require confirm="确认" 才执行 IMPORT_DB=1

- **开发建议**：
  - 用 Python asyncio + aiohttp 实现 HTTP 服务
  - 用 subprocess.Popen 执行 deploy-server.sh，逐行读取 stdout
  - 用文件锁（/tmp/upgrade.lock）实现升级锁
  - systemd 服务：User=root, WorkingDirectory=/opt/myblog, ExecStart=python3 upgrade-agent.py

- **涉及文件列表**：
  - `scripts/upgrade-agent.py`（新建）
  - `scripts/upgrade-agent.service`（新建）

- **验证清单**：
  - [ ] `curl -X POST http://127.0.0.1:28081/upgrade -d '{"version":"v5.0.0","mode":"full"}'` 返回 200 + SSE 流
  - [ ] 并发请求第二个升级 → 返回 409 "升级进行中"
  - [ ] `importDb=true` 但 `confirm != "确认"` → 返回 400 "请输入确认"
  - [ ] `importDb=true` + `confirm="确认"` → 正确传递 `IMPORT_DB=1` 给脚本
  - [ ] `systemctl start upgrade-agent` 服务正常启动
  - [ ] `systemctl status upgrade-agent` 显示 active (running)

- **完成时间**：2026-07-08 22:30
- **解决方案**：Python asyncio + aiohttp 实现 HTTP 服务，监听 127.0.0.1:28081。POST /upgrade 端点接收 JSON body（version/mode/importDb/confirm），通过 subprocess.Popen 执行 deploy-server.sh，逐行读取 stdout 并通过 SSE（event: log/data: line）流式返回。文件锁 /tmp/upgrade.lock（fcntl.LOCK_EX | LOCK_NB）实现并发保护，409 拒绝重复升级。importDb=true 时必须 confirm="确认" 才传递 IMPORT_DB=1。systemd 服务文件 upgrade-agent.service 配置 User=root, Restart=on-failure。GET /status 查询状态，GET /logs 查日志，GET /health 健康检查。
