### 20260814-BUG-001 修复草稿与软删除文章附件越权匿名下载漏洞

- **优先级**：高 (P0)
- **状态**：✅ 已完成
- **完成时间**：2026-08-14 12:05:00
- **涉及文件**：
  - `backend/blog-article/src/main/java/com/blog/article/service/AttachmentService.java`
  - `backend/blog-app/src/test/java/com/blog/ArticleControllerTest.java`
- **根因分析与描述**：
  - 公开下载接口 `GET /articles/{id}/attachment` 在 `AttachmentService.resolveFile()` 仅校验附件记录本身是否被软删，未联动校验所属 `article` 的状态（`status = 1`）和删除标志（`deleted = 0`）。
  - 导致未发布草稿（`status = 0`）和已软删（`deleted = 1`）文章的 Zip 附件可被攻击者通过递增枚举 `articleId` 匿名越权下载。
- **详细修复方案**：
  - 在 `AttachmentService.resolveFile()`（L417）附件软删检查前，增加关联文章状态校验：
    ```java
    Integer articleValid = jdbc.queryForObject(
            "SELECT COUNT(*) FROM article WHERE id = ? AND status = 1 AND deleted = 0",
            Integer.class, a.getArticleId());
    if (articleValid == null || articleValid == 0) {
        log.warn("附件下载拦截：所属文章未发布或已删除 attachmentId={} articleId={}",
                a.getId(), a.getArticleId());
        throw new BusinessException(404, "文章不存在或未发布");
    }
    ```
- **验证清单**：
  - [x] 针对草稿文章（`status=0`）的附件执行匿名下载，断言返回 HTTP 404
  - [x] 针对软删文章（`deleted=1`）的附件执行匿名下载，断言返回 HTTP 404
  - [x] 针对已发布文章（`status=1, deleted=0`）的附件执行下载，断言正常返回 200

### 20260814-BUG-002 修复公开文章接口字段泄露与列表全量正文传输膨胀问题

- **优先级**：高 (P1)
- **状态**：✅ 已完成
- **完成时间**：2026-08-14 12:05:00
- **涉及文件**：
  - `backend/blog-article/src/main/java/com/blog/article/service/ArticleService.java`
  - `frontend/scripts/fetch-routes.js`
  - `frontend/pages/index.vue`
  - `frontend/pages/archives.vue`
  - `frontend/pages/categories.vue`
  - `frontend/pages/tags.vue`
  - `frontend/pages/search.vue`
  - `frontend/pages/post/[slug].vue`
  - `backend/blog-app/src/test/java/com/blog/ArticleControllerTest.java`
- **根因分析与描述**：
  - `ArticleService.toMap(a, true)` 统一包含了 `contentMd`、`createdAt`、`updatedAt`、`status` 等字段，被公开接口 `list()`、`archives()`、`detail()` 无差别调用。
  - 公开列表和归档接口开启 `withContent=true` 导致全量 Markdown 正文下发，单次响应包达数百 KB ~ MB 级；且暴露作者写作/编辑时间线。
  - 前端静态构建脚本 `fetch-routes.js` L61-64 依赖 `r.status === 1`，需同步解耦。
- **详细修复方案**：
  1. `ArticleService` 新增 `toPublicMap(Article a, boolean withContent)`：
     - 白名单字段：`id, title, slug, summary, coverUrl, isPinned, viewCount, categoryId, publishedAt`（若 DB 中 `publishedAt` 为空自动用 `createdAt` 兜底）。
     - `withContent == true` 时才放入 `contentMd`。
     - 彻底排除 `status, createdAt, updatedAt`。
  2. `list()` 与 `archives()` 改调 `toPublicMap(a, false)`，`detail()` 改调 `toPublicMap(article, true)`。
  3. `fetch-routes.js` 调整为 `if (r.slug)` 收集路由，解耦对 `status` 字段的依赖。
  4. 前端页面模板解绑对 `a.createdAt` 的直接依赖，统一使用 `a.publishedAt`。
- **验证清单**：
  - [x] 公开列表 `GET /api/v1/articles` 响应无 `createdAt, updatedAt, status, contentMd`
  - [x] 公开归档 `GET /api/v1/articles/archives` 响应无 `createdAt, updatedAt, status, contentMd`
  - [x] 公开详情 `GET /api/v1/articles/{slug}` 响应包含 `contentMd`，无 `createdAt, updatedAt, status`
  - [x] 运行 `node frontend/scripts/fetch-routes.js` 验证静态路由收集正常
  - [x] 前端各页面日期与文章正常渲染
