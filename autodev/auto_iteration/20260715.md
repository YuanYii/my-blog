### 20260715-BUG-003 | 高 | ✅ 已完成

- **问题现象**：管理后台编辑草稿点「预览」，新标签页打开 `/post/{slug}?preview=1` 后**页面空白 / 无内容**，无法预览草稿（即用户反馈"草稿状态的文章还是无法预览"）。已发布文章预览正常。
- **根因分析（代码层已确诊 + 主导因素待集成测试确认）**：
  - **①（真 bug）`post/[slug].vue` 的 `useAsyncData` 无错误分支**：草稿 slug 不会被 `nuxt generate` 预渲染（仅已发布文章 slug 进 `.routes.json`，见 `nuxt.config.ts` 的 `loadPrerenderRoutes`），所以草稿预览页 **100% 依赖客户端 `useAsyncData` 把 `adminGet('/articles/admin/preview/{slug}')` 拉成功**。一旦该请求返回非 2xx（token 边缘态 / 设备不匹配 / 网络 / 500），`useAsyncData` 的 promise reject → `articleRes.value` 恒为 `undefined` → 模板 `loading = !article.value && articleRes.value === null` 因 `res` 已非 `null`（进入 error 态）而变 `false`，且 `article` 为 `null` → **既不显示 loading、也不显示文章、更不弹错误 toast，就是一片空白**。已发布文章因有预渲染静态 HTML 兜底，同样的失败用户看不出；草稿无兜底，失败即暴露。
  - **②（验证方法缺陷，导致上次假阳性）**：2026-07-15 的 BUG-001「✅ 已完成」仅用**后端 curl + 手动 token/deviceId** 验证了 `adminPreview` 端点返回 200，**从未跑过真实浏览器链路**（新标签页冷启动 SPA → `plugins/auth.client.ts` 插件 `init()` 填 token → 路由加载一个**未被预渲染**的草稿 slug → `useAsyncData`→`useAdminApi`→`AdminAuthFilter` 真实 token/deviceId 生命周期）。curl 用的是"理想态"token，绕过了前端错误路径。
  - **③（部署可达性，待集成测试确认）**：上次"升级"只写进了 `myblog-sim` 容器，而该容器**无宿主机端口映射**、容器 IP 宿主机不可达，用户浏览器打不开它；用户实际测试的环境大概率**没有这次修复的代码**（旧 jar / 旧前端构建）。需在用户可达的环境复现。
  - **④（SPA 回退依赖 `/200.html`，待集成测试确认）**：草稿 slug 靠 nginx `try_files $uri $uri/index.html /200.html`（`docs/nginx/nginx-https.conf` L45）的 `/200.html` 回退加载 SPA；若目标环境构建未生成 `/200.html` 或 nginx 未含该回退，预览标签页会直接 404。
- **修复建议（开发时实施，以集成测试结论为准）**：
  - 前端 `post/[slug].vue`：`useAsyncData` 增加 **error 分支**——预览请求失败时（`articleRes.error` 有值）显示明确错误态（如"预览加载失败：{message}" + 重试按钮），而非静默空白；预览模式单独加 `try/catch` 兜底。
  - 明确"保存后再预览"契约：若草稿从未保存（`form.id` 空、`adminPreview` 按 slug 查不到 → 1001），应在 `edit.vue` 的 `handlePreview` 里先自动保存 / 提示"请先保存"，避免预览一个库里不存在的 slug 导致空白。
  - 部署侧：确保修复后的 jar + 前端构建部署到**用户可达**的环境，并跑通 SPA `/200.html` 回退。
