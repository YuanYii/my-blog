## 🟢 建议

### SUG-001：useAdminSettingsTab.ts load() 失败时静默吞错
- **文件**：`frontend/composables/useAdminSettingsTab.ts`，第 15-20 行
- **描述**：`load()` 的 `catch { /* 默认值 */ }` 静默吞噬异常；网络/鉴权失败时既无 console 输出也无 message 提示，用户看到表单显示的是 `reactive(initial)` 的默认值，可能误以为「服务端返回的就是这些值」。save 失败有 message 反馈，load 失败完全无感知，体验上不对称
- **修复建议**：在 catch 中追加 `console.warn('[useAdminSettingsTab] load failed', opts.endpoint, e)`，或退一步在 message 中显示「加载失败，使用默认值」`message.value = '加载失败，使用默认值'`。本轮 OPT-005 任务卡片明确「重构不重写」，可在下一轮迭代再做

### SUG-002：admin.vue navGroups 子项 icon: 'sub' 是死数据
- **文件**：`frontend/layouts/admin.vue`，第 68-76 行（9 个子项的 `icon: 'sub'` 字段）+ `frontend/components/admin/NavIcon.vue`（无 `name === 'sub'` 分支）
- **描述**：9 个 settings 子菜单项都写了 `icon: 'sub'`，但 `NavIcon.vue` 的 v-if 链未匹配 `name === 'sub'`，且 `SidebarNav.vue` 第 54 行渲染子项时用的是 `<span class="admin-nav-subdot">` 装饰点（CSS 实现），并未读取子项的 `icon` 字段。`icon: 'sub'` 写入但永不渲染 → 死数据
- **修复建议**：删除 9 个子项的 `icon: 'sub'` 字段，并在 `NavItem` 类型中把 `icon` 改为可选 `icon?: string`；或保留 `icon` 必填但把子项改为 `icon: 'chevron-right'` 之类的真实 name。本轮以「重构不重写」为原则，可在下一轮迭代做

### SUG-003：组件大量使用 inline style，与项目主流 class-based 风格混用
- **文件**：`frontend/components/admin/SidebarNav.vue`（多处 `style="flex: 1; ..."`）+ `frontend/components/admin/UserChip.vue`（第 10 行整段 inline）+ `frontend/components/admin/settings/SaveBar.vue`（第 7、11 行）
- **描述**：3 个新组件大量使用 `style="..."` inline 样式（margin/padding/gap/font-size 等）。与项目已有 admin 组件中部分 inline + 部分 class 的混用风格保持一致，但若要提升可维护性，建议把可复用的样式提取到 `main.css` 或组件级 `<style scoped>` 块中
- **修复建议**：将 SaveBar 的「保存按钮 + message」横排样式抽到 `.admin-save-bar` 类（CSS 变量统一颜色），UserChip 的胶囊样式抽到 `.admin-user-chip` 类。可在下一轮迭代做（属于可读性优化，不影响行为）
