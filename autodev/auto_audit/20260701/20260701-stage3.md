## 🟡 警告（合并去重）

### WARN-001（DEV-001）：`AttachmentService.upload` 大事务包裹单条 INSERT + 文件落盘

- **文件**：`backend/blog-article/src/main/java/com/blog/article/service/AttachmentService.java`，第 73 行起
- **维度**：性能
- **描述**：`@Transactional` 包裹了 `file.transferTo(target)` + `attachmentMapper.insert(a)`。文件 IO 是慢操作（5MB 磁盘写入约 50-200ms），整段持事务 → SQLite WAL 期间其他写阻塞；MyBatis-Plus @Transactional 默认 propagation=REQUIRED，会共用外层事务（如果将来在 Controller 加 `@Transactional` 包多步）。**未实际破坏功能**（无外层事务时事务短，单 INSERT 提交快），但设计上把慢 IO 放进事务范围是反模式。
- **修复建议**：
  - 方案 A：拆分成两个方法 + `TransactionTemplate` 编程式事务（仅包裹 INSERT，文件 IO 在事务外）
  - 方案 B：保留现状但加注释说明（"文件 IO 在事务内是因为并发竞态 catch UNIQUE 需要回滚文件落盘"——确实如此，这是为了一致性的权衡）
  - **推荐方案 B + 注释**：本场景下文件 IO 与 DB INSERT 必须原子（catch UNIQUE 后要删文件），拆出去反而引入更复杂的补偿逻辑。
- **是否阻塞**：否（性能影响在 5MB 文件场景下不明显，单附件上传不是高频路径）

### WARN-002（DEV-001）：`AttachmentController.streamDownload` 走 `ResponseEntity<InputStreamResource>` 但未设 `Cache-Control`

- **文件**：`backend/blog-article/src/main/java/com/blog/article/controller/AttachmentController.java`，第 50-77 行
- **维度**：规范
- **描述**：公开下载响应未设置 `Cache-Control` / `ETag`。浏览器每次都会重新请求，浪费带宽；同时 nginx 也不会缓存。**对个人博客（流量小）无实际影响**，但作为规范缺漏值得标注。
- **修复建议**：加 `Cache-Control: private, max-age=3600` + `ETag: "<fileSize>-<updatedAt hash>"`（用 attachment.updatedAt 哈希生成）。**优先级低**。
- **是否阻塞**：否

### WARN-102（BUG/OPT 第二轮）：`useDialog.open` 7 字段兜底默认值与 30+ 调用方类型契约未同步

- **描述**：BUG-003 修复时给 `state.value` 7 个字段（confirmText/cancelText/danger/prompt/promptLabel/promptPlaceholder/promptDefault）补 `?? ### WARN-103（BUG/OPT 第二轮）：`posts.vue.handleHardDelete` 用 `$dialog.prompt` 输入 DELETE 校验，前端逻辑简单可被剪贴板绕过

- **是否阻塞**：否（前端 UX 引导，不是安全屏障；后端鉴权已足够）
