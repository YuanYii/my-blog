## 🟡 警告

### WARN-001：AuditLogAspect 反射解析 annotation 每请求都做
- **文件**：`backend/blog-auth/src/main/java/com/blog/auth/service/AuditLogAspect.java:160-194`
- **维度**：性能
- **描述**：aspect 每次拦截都通过 `method.getAnnotations()` + `method.getDeclaringClass().getAnnotation()` 反射解析 HTTP method + 拼接 path。虽然 controller 方法数量有限（约 30 个），但每请求都反射一遍有微开销。
- **修复建议**：维护一个 `Map<Method, ResolvedRoute>` 缓存（ConcurrentHashMap），第一次反射后缓存 resolved（httpMethod + fullPath + target）。后续直接 Map.get。class 加载后 method 总数固定，缓存不会无限增长。

### WARN-002：SettingsMdImporter 单体类职责过重（解析 + 校验 + 事务）
- **文件**：`backend/blog-settings/src/main/java/com/blog/settings/service/SettingsMdImporter.java`
- **维度**：规范
- **描述**：类长 290 行，包含 YAML 解析、4 段校验、4 段写入、事务边界、临时文件管理 5 职责。
- **修复建议**：① 抽 `parseFrontmatter` 到独立 `FrontmatterParser` 静态工具；② 抽 4 段 validate* 方法到 `SettingsMdValidator`（与 `SettingsMdTemplate` 配对）；③ 主类只剩"调用 + 事务 + 临时文件"3 件事，预计降至 100 行内。

### WARN-003：AuditLogAspect 的 TargetTable 写在 @Aspect 内部类
- **文件**：`backend/blog-auth/src/main/java/com/blog/auth/service/AuditLogAspect.java:170-194`（TARGET_TABLE）
- **维度**：规范
- **描述**：aspect 既是切面代码又是模块映射表，单文件混关注点。新增模块时容易漏改。
- **修复建议**：抽 `AuditLogTargetRegistry`（独立类 + ConcurrentHashMap<String, String>），提供 `register(prefix, target)` API 与 `resolve(path)` 方法；与 `AuditLogService.TARGET_OPTIONS` 共享同一常量源（避免双处维护）。

## 🔴 严重

### CRIT-001：SettingsMdImporter snakeYAML 默认构造器允许任意 Java 类型反序列化
- **文件**：`backend/blog-settings/src/main/java/com/blog/settings/service/SettingsMdImporter.java:130`
- **维度**：安全
- **描述**：`new Yaml().load(yaml)` 默认使用 `Constructor` 而非 `SafeConstructor`，允许反序列化任意 Java 类型。攻击者构造恶意 md（如 `!!javax.script.ScriptEngineManager [...]`）可触发 RCE（CVE-2022-1471 模式）。虽然当前端点要求 admin + device 白名单，但任何拥有 admin 权限的恶意设备都可利用。
- **修复建议**：① 改用 `new Yaml(new SafeConstructor()).load(yaml)` —— 限制只能反序列化 Map/List/String/Number/Boolean 等基础类型，禁用任意 Java 类加载；② 或用 `new Yaml(new Constructor(new LoaderOptions()))` 加 `LoaderOptions.setAllowUnknownTags(false)` 双重保险；③ 紧急性高：snakeyaml 1.30 < 2.0 都默认开启 type tag。
- **实际修复**（2026-07-01 21:03 stage 3 阶段立即修复，不等下轮）：改用 `new Yaml(new SafeConstructor(new LoaderOptions())).load(yaml)` —— 双重保险（SafeConstructor + 新建 LoaderOptions）。myblog-sim 实测上传含 `!!javax.script.ScriptEngineManager` type tag 的恶意 md → 400 "could not determine a constructor for the tag ...ScriptEngineManager" ✅。

## 🟢 建议

### SUG-001：AuditLog.record() 缺失败计数（运维可观测性）
- **文件**：`backend/blog-auth/src/main/java/com/blog/auth/service/AuditLogService.java:48-62`
- **描述**：当前 `record()` 失败仅 `log.warn`，无 metrics。建议加 Micrometer counter（`audit_log_record_failures_total`）便于 Grafana 监控。
- **建议**：下次接入 Micrometer 时一并加。

### SUG-002：audit_logs 长期积累未设 TTL
- **文件**：`docs/sql/schema-sqlite.sql:audit_log`
- **描述**：当前表无限增长，个人博客量级 ≤10/天几乎无压力，但企业级部署建议加按月分区或定期清理策略。
- **建议**：下一迭代加 `cleanup_audit_logs()` 定时任务，保留 90 天。

### SUG-003：useSettingsEventBus 缺 TypeScript 泛型约束
- **文件**：`frontend/composables/useSettingsEventBus.ts`
- **描述**：`Handler` 类型固定为 `SettingsEventPayload`，未来加新事件类型时扩展性受限。
- **建议**：改为 `useSettingsEventBus<T extends SettingsEventType>()` 模式，加 event→payload 映射类型。

### SUG-004：SettingsMdUploader 进度条写死百分比
- **文件**：`frontend/components/admin/settings/SettingsMdUploader.vue:67-69`
- **描述**：进度条 hardcode `progress.value = 10` + `= 100`，没用真实上传进度。
- **建议**：用 `XMLHttpRequest` 的 `upload.onprogress` 事件拿真实进度（`useAdminApi.upload` 是 `$fetch` 不暴露进度，可考虑为这个特定端点重写一次）。

### SUG-005：audit-logs.vue 的 pageNo 计算反序但 total 改动会触发重渲染
- **文件**：`frontend/pages/admin/audit-logs.vue:153`
- **描述**：`rowNo(i) = total.value - (page.value - 1) * size.value - i` 在 total 变化时整列表重渲染。
- **建议**：分页器切换时短暂 loading 即可掩盖闪动；或使用 `key` 触发 `<TransitionGroup>` 平滑过渡。

### SUG-006：SettingsMdImporter 字段白名单与 template 字段白名单耦合
- **文件**：`backend/blog-settings/src/main/java/com/blog/settings/service/SettingsMdImporter.java:163-170`
- **描述**：profile 段 5 字段写入走 `userMapper.update` 但白名单写在 `SettingsMdTemplate.PROFILE_FIELDS`，两边要手工对齐。
- **建议**：把 `applyProfile` 的 `uw.set(field, ...)` 也用 `SettingsMdTemplate.PROFILE_FIELDS` 遍历 + 用 entity 字段注解驱动字段名映射（避免 fieldToColumn 写死）。
