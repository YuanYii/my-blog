## 四、Stage 2 二轮开发期修复（一体修掉）

### 修复 R-A：adminList 改 JdbcTemplate 绕过 MP 全局 logic-delete

- **症状**：`qw.eq("deleted", 1/all)` 被 MyBatis-Plus 全局 `logic-delete-field: deleted` 配置强制加 `AND deleted=0`，del=1/all 三态返 0 条
- **影响**：BUG-002 后端 spec 要求 adminList 三态过滤，原始 MP Wrapper 写法不可行
- **修复**：`ArticleService.adminList`（line 153-241）整段重写：JdbcTemplate + 动态 WHERE/ORDER BY 字符串拼接 + ADMIN_SORT_FIELDS 白名单（与 AttachmentService.list 同模式）；adminList 返回结构与原版 100% 等价，**新增字段 attachmentCount**（OPT-001 一并）
- **验证**：`deleted=0/1/all` 实测 6/9/15 ✓

### 修复 R-B：ArticleService.restore / hardDelete 内部 entity 查询绕过 MP logic-delete

- **症状**：`articleMapper.selectById(id)` 对 `deleted=1` 文章返 null（被 MP global logic-delete 拦截），后续 `if (existing == null) throw 1001` 误报"文章不存在"
- **影响**：操作员调硬删除 / 恢复 → 看到 1001 "文章不存在" → 误以为是 bug
- **修复**：`ArticleService.restore`（line 499-513）+ `ArticleService.hardDelete`（line 481-498）内部 `articleMapper.selectById` → `jdbc.queryForList("SELECT id, slug FROM article WHERE id = ?", id)`；软删/已删文章都能找到 entity，后续 UPDATE/DELETE 不受阻
- **验证**：实测 8235（soft-deleted）restore 200 + 8232（soft-deleted）hard-delete 200 + DB 实际 deleted/DELETE FROM 生效 ✓
