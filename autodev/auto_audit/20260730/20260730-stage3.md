## 🟡 警告

### WARN-001：日志消息未做输入清洗
- **文件**：`backend/blog-settings/src/main/java/com/blog/settings/controller/SettingsController.java`，第 507 行
- **维度**：安全
- **描述**：`message.trim()` 后直接拼接到日志消息，未过滤换行符（`\n`、`\r`）和特殊字符。攻击者可通过注入换行符伪造多条日志记录（Log Injection），干扰日志审计。
- **修复建议**：对 message 做单行清洗，移除或替换换行符：
  ```java
  String cleaned = message.trim().replaceAll("[\\r\\n]+", " ");
  String logMessage = prefix + cleaned;
  ```

## 🟢 建议

### SUG-001：timestamp 和 thread 参数仅做透传未实际使用
- **文件**：`backend/blog-settings/src/main/java/com/blog/settings/controller/SettingsController.java`，第 479-481 行
- **描述**：接口接收了 `timestamp` 和 `thread` 参数，但实际日志输出由 Logback 自动生成时间戳和线程名。这两个参数仅在最后的 `log.info("模拟日志已打印：level={} count={} thread={}", ...)` 中使用 thread，timestamp 完全未使用。不影响功能，但会造成调用方困惑。
- **建议**：可考虑在日志消息中附带用户输入的原始信息，或在接口文档中说明这些字段仅用于前端展示。

### SUG-002：handleReset 中重复重置 message 字段
- **文件**：`frontend/components/admin/settings/LogSimulatorDialog.vue`，第 51-54 行
- **描述**：`handleReset()` 调用 `initDefaults()` 已经将 `message.value = ''`，随后又重复赋值 `message.value = ''`，属于冗余代码。
- **建议**：移除 `handleReset` 中的 `message.value = ''` 行，或直接调用 `initDefaults()` 即可。
