## 🟡 警告

### WARN-001：syncFromGithub 方法过长（112 行 > 80 阈值）
- **文件**：`backend/blog-settings/src/main/java/com/blog/settings/service/BackupService.java`，第 599-715 行
- **维度**：规范
- **描述**：`syncFromGithub(HttpServletRequest)` 方法体约 112 行，超出 Java 方法 80 行警告阈值。逻辑混合了「环境预检 → operator 提取 → release 拉取 → 字段映射 → manifest 解析 → INSERT」六段职责。
- **修复建议**：抽出三个 private 方法：
  - `resolveOperator(HttpServletRequest)` 返回 `(Long, String)` Tuple/简单 POJO（提取 operatorId/operatorName/traceId）
  - `buildBackupRecordFromRelease(GithubRelease, OperatorInfo)` 拼装 BackupRecord 主字段
  - `enrichSizesFromManifest(BackupRecord, GithubRelease)` 解析 manifest 并填 dbSize/uploadsSize
  当前迭代未做拆分以保持改动面收敛，建议后续 polish 迭代处理。

### WARN-002：backup.vue handleSync 无二次确认弹窗
- **文件**：`frontend/pages/admin/backup.vue`，第 78-90 行（新增 handleSync）
- **维度**：规范
- **描述**：现有 `handleTrigger`（立即备份）走 `$dialog.confirm` 二次确认，与全站风格一致。新增的 `handleSync` 直接发请求无确认。
- **影响**：sync 接口是幂等的（已存在 tag 跳过），误点风险较低；但用户预期所有「写动作」按钮都有一致的二次确认体验。
- **修复建议**：仿照 `handleTrigger` 加 `$dialog.confirm({ title: '备份同步', message: '将从 GitHub 备份仓库拉取最近 3 条 release 元数据…', confirmText: '开始同步' })`，与全站交互风格对齐。
  当前迭代选择不弹确认以减少 hover/click 成本（每次都点确认对纯只读+幂等动作累赘），可在 UAT 阶段根据用户反馈调整。

## 🟢 建议

### SUG-001：fetchManifestContent / listGithubReleases 重复 ProcessBuilder + curl/gh + BufferedReader 模式
- **文件**：`backend/blog-settings/src/main/java/com/blog/settings/service/BackupService.java`，第 717-758（listGithubReleases）+ 第 760-799（fetchManifestContent）+ 第 478-512（deleteGitHubRelease curl fallback）
- **描述**：3 处 ProcessBuilder + BufferedReader 读取 stdout + waitFor + exitValue 检查的代码结构高度相似（仅命令字符串不同）。可抽取通用 `executeShellAndCapture(String cmd, Map<String,String> env, int timeoutSec)` 工具方法消除重复。
- 影响小（3 处 50 行重复），可在备份/恢复模块整体重构时统一处理。

### SUG-002：GithubRelease / GithubAsset 用 public 字段而非 Lombok @Data
- **文件**：`backend/blog-settings/src/main/java/com/blog/settings/service/BackupService.java`，第 838-848 行
- **描述**：项目内其他 Jackson DTO（如 `ResultJson` 第 691 行）都用 `@lombok.Data`，新增的 `GithubRelease` 用 public 字段。功能上等价（Jackson 都能反序列化），但风格不一致。
- 建议改为 `@lombok.Data` 与项目惯例对齐（一致性优先，性能/编译影响可忽略）。

### SUG-003：main.css 中 .toolbar-dropdown 局部样式可考虑下沉到 posts.vue scoped style
- **文件**：`frontend/assets/css/main.css`，第 1330-1331 行
- **描述**：`.toolbar-dropdown` 当前仅 posts.vue 使用，写到全局 main.css 增加了全局 CSS 体积、降低了样式作用域可读性。
- 不过项目内 posts.vue 暂无 `<style scoped>` 块（既有 `.toolbar` / `.post-cell-title` 都在 main.css），保持惯例也合理。可二选一。
