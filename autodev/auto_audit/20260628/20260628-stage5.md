## 测试基础设施说明（本轮新引入）

### 临时 e2e 服务器 `_e2e-server.mjs`

**位置**：`frontend/_e2e-server.mjs`（112 行，Node 原生 http）

**职责**：
- 静态 serve `.output/public`（即 nuxt generate 产物）
- `/api/*` 反代到 `http://localhost:8080`（Spring Boot 后端）
- 端口 3000

**为什么需要这个**：
1. `npx serve .output/public` 不支持 /api proxy → 浏览器请求 `/api/v1/...` 会 404
2. `nuxt dev` 跑 e2e 太重（HMR + 1.3GB 内存 + 107% CPU，长时间跑测试会被压垮）
3. 现状：playwright.config.ts 没有 webServer 配置，依赖外部服务

**后续动作**：
- 短期：保留在 `frontend/_e2e-server.mjs`，下次 e2e 直接 `node _e2e-server.mjs &` 启服务
- 长期建议（不在本轮范围）：playwright.config.ts 加 `webServer: { command: 'node _e2e-server.mjs', port: 3000, reuseExistingServer: true }`，让 Playwright 自启服务，CI 友好

### 测试设备 pre-approve

**位置**：`backend/blog.db` admin_device 表新增 `e2e-keyboard-test-device` 记录（status=approved）

**为什么需要这个**：
- useDevice.ts 自动生成 UUID 存 localStorage（`blog_admin_device_id` key）
- 新 device 默认 status=pending → 后端 AdminAuthFilter 2001 拒 → 登录失败
- 测试的 fresh browser context 每次都生成新 deviceId，永远在 pending

**当前做法**：
- login() helper 用 `page.evaluate` 强制覆盖 localStorage 为预授权 deviceId
- 重启 backend 让 in-memory 缓存 reload（实际上 SQLite 状态持久了，不用重启）

**后续动作**：
- 短期：保留 pre-approve 设备，跑前检查 `admin_device` 表有 `e2e-keyboard-test-device`
- 长期建议（不在本轮范围）：playwright global setup 写脚本，先 truncate + insert 一条预授权设备，CI 自包含

### 测试结构

- `frontend/tests/dialog-keyboard.spec.ts` 新增 10 个 case
- 覆盖：GlobalDialog confirm/prompt、4 个内联 modal、IME composing、防重、焦点环
