## 🟡 警告

### WARN-001：NavBar.vue 重复 `onMounted` + `addEventListener`，未在 `onBeforeUnmount` 清理
- **文件**：`frontend/components/NavBar.vue`，第 142-149 行 + 第 173-186 行
- **维度**：规范
- **描述**：NavBar 当前有两个独立的 `onMounted` 块，分别注册 `document.addEventListener('click', ...)` 和 `document.addEventListener('keydown', ...)`。两个 click 监听独立判断各自的状态（菜单 / 搜索弹层），逻辑正确但有以下问题：
  1. **无 `onBeforeUnmount` 清理**：监听器永远留在 document 上。虽然 SPA 路由切换时 NavBar 实例会被销毁，但 listener 仍持有对 NavBar scoped ref 的闭包（虽然 ref 也被 GC）—— 严格说没有内存泄漏，但 listener 数量随 SPA 多次进出 NavBar 路由而累积（实际项目是单页 NavBar，影响小）
  2. **重复 onMounted 调用**：同一个 setup 函数里两次 `onMounted(...)` 都能注册，Nuxt 兼容但**不是推荐写法**——推荐合并成一个 `onMounted` 块
- **影响**：长会话（不停打开关闭菜单 + 搜索弹层）下 listener 闭包持有；进入/离开 admin 后台再回前台时，旧 listener 闭包已 stale
- **修复建议**：
  ```ts
  function onDocClick(e: MouseEvent) {
    if (isMenuOpen.value && navRef.value && !navRef.value.contains(e.target as Node)) closeMenu()
    if (isSearchOpen.value && searchRef.value && !searchRef.value.contains(e.target as Node)) closeSearch()
  }
  function onDocKeydown(e: KeyboardEvent) {
    if (e.key === 'Escape' && isSearchOpen.value) closeSearch()
  }
  onMounted(() => {
    if (!import.meta.client) return
    document.addEventListener('click', onDocClick)
    document.addEventListener('keydown', onDocKeydown)
  })
  onBeforeUnmount(() => {
    document.removeEventListener('click', onDocClick)
    document.removeEventListener('keydown', onDocKeydown)
  })
  ```

### WARN-002：about.vue 与 SiteFooter.vue RSS 显隐双控策略不一致
- **文件**：`frontend/pages/about.vue` 第 102 行 + 第 181 行 vs `frontend/components/SiteFooter.vue` 第 21 行
- **维度**：规范（行为一致性）
- **描述**：
  - **SiteFooter.vue**：`showRss = siteFlags.enableRss && !!social.rss`（双控，开关关或 URL 空都隐藏）
  - **about.vue**：`<a v-if="siteFlags.enableRss" :href="social.rss || '/rss.xml'">`（只控开关，URL 空时 fallback `/rss.xml` 仍显示）
- **影响**：admin 关闭 enableRss 时两处都隐藏，行为一致；admin 开启 enableRss 但没配 social.rss 时，**footer 隐藏、about 仍显示「RSS /rss.xml」**——读者从 footer 看不到 RSS 入口，但能在 about 看到，体验割裂
- **修复建议**：两处统一为 `siteFlags.enableRss && !!social.rss` 双控，或者在 about.vue 也定义 `showRss` computed 共享

### SUG-001：search.vue catch (e: any) 变量未使用
- **文件**：`frontend/pages/search.vue` 第 29 行
- **描述**：`} catch (e: any) {` 但 catch 块内未引用 `e`，TS noUnusedParameters 规则会警告

### SUG-002：search.vue articles 字段名兼容冗余
- **文件**：`frontend/pages/search.vue` 第 27 行
- **描述**：`res.data?.records || res.data?.list || []`——同时兼容 `records` 和 `list` 两种字段名。后端分页返回约定是 `records`，如前端确认后端不会返 `list`，可收敛为 `res.data?.records || []`
- **建议**：与后端 `Result<Page<...>>` 结构对齐，仅取 `records`；如确需兼容历史接口，保留但加注释说明

### SUG-003：NavBar 搜索 input 缺 a11y label
- **文件**：`frontend/components/NavBar.vue` 第 53-60 行
- **描述**：搜索弹层里的 `<input type="search">` 仅用 `placeholder="搜索文章…"`，对屏读器不可达
- **建议**：加 `aria-label="搜索文章"` 或关联 `<label class="sr-only">` 元素

### SUG-004：NavBar 搜索弹层 keyword 状态生命周期未注释
- **文件**：`frontend/components/NavBar.vue` 第 153 行
- **描述**：`searchKeyword` 是 setup 级 ref，弹层关闭/打开时不会被清空（用户上次输入的词下次还在）
- **建议**：明确这是有意的（保留上下文）还是无意的（弹层关闭时清空）；加注释说明，避免后续维护者困惑
