# v5.3.1 部署方案统一

**日期**: 2026-07-09  
**类型**: 功能增强  
**影响**: 部署脚本、升级代理、后端控制器、前端页面

## 背景

手动升级和线上升级（通过 upgrade-agent）存在差异：
- 手动升级：`./deploy-server.sh v5.3.10`（需要传入版本号）
- 线上升级：`upgrade-agent` 调用 `deploy-server.sh` 时也传入版本号

这导致版本号管理不一致，且用户需要手动指定版本号。

## 改动

### 1. deploy-server.sh
- **下载脚本统一路径**: 从 `releases/latest/download/deploy-server.sh` 下载最新脚本
- **执行时传版本号**: 仍需要传入版本号参数
- **自动获取最新版本**: 当未传入版本号时，自动从 GitHub API 获取最新 release 的 tag（`LOCAL_SIM=1` 模式除外）
- **向后兼容**: 仍然支持传入版本号（`$0 <tag>`）

### 2. upgrade-agent.py
- **移除版本号必填校验**: `version` 字段现在可选
- **统一调用方式**: 不传版本号时，让 `deploy-server.sh` 自动获取最新版本
- **状态更新**: 从 `deploy-server.sh` 输出中解析实际版本号并更新状态

### 3. UpgradeController.java
- **version 可选**: 不再强制要求传入 `version` 参数
- **自动获取**: 当 `version` 为空时，调用 `UpgradeService.getLatestVersion()` 获取最新版本
- **新增方法**: `UpgradeService.getLatestVersion()` 从 GitHub API 获取最新 release tag

### 4. 前端 upgrade.vue
- **按钮状态**: 移除 `!effectiveVersion` 的禁用条件，允许不选版本直接升级
- **提示信息**: 更新说明文字，说明支持自动获取最新版本
- **确认对话框**: 显示"最新版本"而非空字符串

## 使用方式

### 下载部署脚本（不带版本号）
```bash
# 从 GitHub 下载最新版本的部署脚本
GITHUB_REPO=YuanYii/my-blog-prov
curl -L "https://github.com/$GITHUB_REPO/releases/latest/download/deploy-server.sh" \
    -o "deploy-server.sh"
chmod +x "deploy-server.sh"
```

### 执行部署脚本（传版本号）
```bash
# 生产环境：需要传入版本号
sudo DEPLOY_MODE=full ./deploy-server.sh v5.3.10

# 本地 Docker 测试：需要传入版本号
LOCAL_SIM=1 ./deploy-server.sh v5.3.10
```

### 通过前端升级
- 选择版本列表中的版本
- 或手动输入版本号
- 或不选版本，直接点击"开始升级"（自动获取最新版本）

## 兼容性

- **完全向后兼容**: 仍然支持传入版本号
- **无破坏性变更**: 现有部署方式不受影响
- **新增能力**: 支持自动获取最新版本
