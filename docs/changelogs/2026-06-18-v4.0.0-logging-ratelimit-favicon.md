## 二、全站 IP 限流 + 封禁（防刷流量）

### 新增文件

- `backend/blog-app/src/main/java/com/blog/common/security/IpRateLimitFilter.java`（114 行）
- `backend/blog-auth/src/main/java/com/blog/auth/service/IpBanService.java`（144 行）
- `backend/blog-auth/src/main/java/com/blog/auth/entity/IpBan.java`
- `backend/blog-auth/src/main/java/com/blog/auth/mapper/IpBanMapper.java`

### 依赖变更

- `backend/blog-auth/pom.xml` — 加 `spring-boot-starter-data-redis`（Redis 热路径计数 + 封禁标记）

### 设计要点

- `@Order(Ordered.HIGHEST_PRECEDENCE + 1)`：在 TraceIdFilter 之后，业务 filter 之前
- Redis 计数走请求热路径（O(1) INCR），DB 只在"触发封禁那一刻"写一行（避免 SQLite 单写者锁被刷爆）
- Redis 故障 → fail-open 放行（不因限流层抖动拖垮全站）
- `IpBanService.warmUpFromDb()` 启动回灌：DB 里未过期的封禁 → Redis 恢复（防 Redis 重启缓存丢失空窗期）

### 配置项（`application.yml`）

```yaml
blog:
  security:
    ip-rate-limit:
      enabled: true                        # 总开关
      max-requests-per-second: 10          # 1 秒内超阈值自动封禁
      ban-duration-minutes: 30             # 封禁时长
```
