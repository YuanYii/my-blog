# 2026-06-17 v2.7.0: Nuxt 改全静态（nuxt generate + nginx serve）

## TL;DR

前端从"SSR-off + node 服务跑"改成"nuxt generate + nginx 静态服务"——**1C2G 服务器省 150-250MB 内存**。配套每日 cron rebuild 脚本，新文章最迟 24h 内可见。

---

## 1. 范围

| 项 | 改造 |
|---|---|
| 构建命令 | `nuxt build` → **`nuxt generate`**（产出 `.output/public/` 静态文件） |
| 运行时 | node 20 + Nitro server → **nginx alpine 静态服务** |
| 后端 JVM | 256MB heap → **可提到 384MB**（释放的内存） |
| 公开页 SEO | CSR 空 HTML → **预渲染 13 个静态 HTML**（百度/Google 可收录） |
| admin 路由 | 不预渲染（**保持 SPA 客户端渲染**） |
| 新文章发布 | 立即可见 → **每日凌晨 cron rebuild**（0-24h 延迟） |

---

## 2. 改动详情

### 2.1 `frontend/nuxt.config.ts`

加 `nitro.prerender` 配置：

```ts
nitro: {
  prerender: {
    routes: ['/', '/about', '/archives', '/tags'],   // 公开页入口
    crawlLinks: true,                                  // 从首页爬 <a> → 预渲染 /post/xxx
    failOnError: false,                                // 单个 slug 404 不阻塞构建
    ignore: ['/admin', '/admin/**', '/api/**'],        // admin 不预渲染
  },
},
```

**关键点**：
- `crawlLinks: true` 自动从首页"最新文章"卡片爬出所有文章 URL → 预渲染每篇文章
- `ignore: '/admin/**'` 排除 admin（登录后才看 + 内容因用户而异，预渲染无意义）
- `failOnError: false` 防止"文章被删了但首页还有链接"阻塞整次构建

### 2.2 `frontend/package.json`

```diff
- "build": "nuxt build",
+ "build": "nuxt generate",
```

`nuxt build` 输出 `.output/server/index.mjs`（要 node 跑）
`nuxt generate` 输出 `.output/public/index.html` + 静态资源（直接 nginx serve）

### 2.3 `frontend/Dockerfile`

**改前**：node:20-alpine 跑 `.output/server/index.mjs`，吃 150-250MB
**改后**：nginx:alpine 跑 `.output/public/`，吃 10-20MB

镜像体积也从 ~200MB 降到 ~50MB。

**关键设计**：
- `try_files $uri $uri/ /index.html;` → SPA fallback，admin 路由也能走
- `index.html` 强制 `no-cache` → 部署后立即生效
- 静态资源 `immutable` 长缓存 7 天 → 减少回源
- `/healthz` 端点 → 部署脚本健康检查

### 2.4 `frontend/composables/useAuth.ts`

移除 SSR 阶段从 cookie 读 token 的逻辑（12-18 行）：

```diff
- // 从 cookie 字符串里解析 token
- const readTokenFromCookie = (raw: string | undefined | null): string | null => { ... }
- // SSR 阶段：从 request headers 读 cookie 恢复 token
- if (import.meta.server) {
-   const headers = useRequestHeaders(['cookie'])
-   if (!token.value) {
-     token.value = readTokenFromCookie(headers.cookie)
-   }
- }
```

**原因**：全静态化后 `import.meta.server` 永远是 `false`，这段是死代码。
**影响**：零（cookie 写入逻辑保留，admin 登录态靠 `auth.client.ts` 插件 + `localStorage` 兜底，跟原来一致）。

### 2.5 `frontend/middleware/admin-auth.ts`

移除 `if (import.meta.server) return` 判断——同样死代码。

### 2.6 `scripts/rebuild-static.sh`（新增）

每日 cron 跑的重建脚本，工作流：

1. 备份当前 `.output/public/` → `.output/.history/public-{timestamp}/`（保留 3 份）
2. 拉最新代码（`git pull --ff-only`，失败不阻塞）
3. 跑 `nuxt generate`（30-90s，吃 200-300MB）
4. 校验 `.output/public/index.html` 存在
5. 同步到 nginx 服务目录 `/var/www/blog/`（**先同步到临时目录再原子 rename**）
6. `nginx -s reload`（保险）
7. 健康检查 `/healthz`
8. 写日志 `/var/log/myblog-rebuild.log`

**容错设计**：
- 构建失败时日志提示回滚命令
- 备份保留 KEEP_BUILDS 份（默认 3）
- 所有错误都写日志（不靠 stdout）

**安装**：

```bash
# 复制到 ECS
scp scripts/rebuild-static.sh deploy@ecs:/opt/myblog/scripts/

# crontab -e（deploy 用户）
0 3 * * * bash /opt/myblog/scripts/rebuild-static.sh
```

## 3. 部署架构对比

| 维度 | v2.6.0（SSR-off + node） | v2.7.0（全静态 + nginx） |
|---|---|---|
| 前端进程 | node + Nitro server | **nginx** |
| 前端内存 | 150-250 MB | **10-20 MB** |
| 后端 JVM heap 上限 | 256 MB（极限） | **384 MB**（释放 130MB+） |
| Docker 镜像 | ~200 MB | **~50 MB** |
| 公开页首屏 | 客户端渲染（等 JS 跑） | **预渲染 HTML（首屏直出）** |
| 公开页 SEO | 无 | **有**（百度/Google 可收录） |
| 新文章延迟 | 即时 | **0-24h**（每日 cron 凌晨 3 点） |
| 部署复杂度 | 维护 node 进程 | **静态文件** |

## 5. 风险 & 缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 新文章 0-24h 延迟可见 | 读者晚一天看到 | 个人博客可接受；频率提升后改事件触发 |
| 构建时短暂吃 200-300MB | 凌晨 3 点构建时与访问重叠 | 选**凌晨低峰**（已选 3 点），构建 ~60s 完事 |
| 部署后浏览器看到旧 HTML | 缓存问题 | `index.html` 设 `no-cache, no-store`（已配） |
| crawlLinks 漏爬 | 新文章没被预渲染 | 公开页"最新文章"卡片必须挂首页 → 必被爬到；如担心可手动加 `routes: ['/post/spring-boot-jwt-security', ...]` |
| 构建失败未通知 | 博客长期不更新 | `rebuild-static.sh` 写日志，配套告警脚本（v2.6.0 backlog 中） |
| nginx reload 失败 | 用户继续看旧文件 | 不影响新文件访问（nginx 直接读文件，不缓存） |

## 6. 部署清单（v2.7.0 配套）

1. **本地 build 验证**：`cd frontend && npm run build` → 看 `.output/public/` 里有几个 HTML
2. **本地预览**：`npx serve .output/public -p 3000` → 访问 `http://localhost:3000`
3. **Docker 镜像构建**：
   ```bash
   docker build --build-arg NUXT_PUBLIC_API_BASE=https://yourname.com/api/v1 \
     -t myblog/frontend:latest frontend/
   ```
4. **推送 + 部署**（按 v2.6.0 deploy-sqlite.sh 流程）
5. **配 cron**（每日凌晨 3 点 rebuild）：
   ```bash
   scp scripts/rebuild-static.sh deploy@ecs:/opt/myblog/scripts/
   crontab -e   # 加：0 3 * * * bash /opt/myblog/scripts/rebuild-static.sh
   ```
6. **验证**：
   - `curl -I https://yourname.com/` → 200 + `text/html`（不是空 SPA 包）
   - View Source → 看到文章标题（说明 HTML 已预渲染）
   - `curl https://yourname.com/api/v1/articles` → 走 Spring Boot

## 7. 后续优化（backlog）

- **事件触发 rebuild**：写文章时自动触发（从 24h 延迟降到 30-60s）—— 视写文章频率决定
- **预渲染缓存 + 增量构建**：nuxt generate 改成只构建新增/修改的文章
- **CDN 加速**：把 `/var/www/blog/` 同步到阿里云 OSS / CDN，国内访问加速
- **告警脚本**：build 失败发邮件/微信（v2.6.0 backlog）
