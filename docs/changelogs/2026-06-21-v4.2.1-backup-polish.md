## 背景

v4.2.0 数据备份功能当天上线，4 处未走完整设计 / 缺关键体验：
1. 数据备份页表格风格与其它 admin 页（posts / comments / categories 等）不一致 —— 全内联 style + 手写分页，与 `.table` / `.admin-pagination` 设计系统脱节
2. 失败 toast 没有 traceId —— GlobalExceptionHandler 兜底 500 已拼 traceId 后缀，但业务异常（BACKUP_CONFLICT 等）没拼，owner 排查不便
3. 操作人显示成 `uid:1` —— `BackupService.resolveOperatorName` 用 uid 反查失败兜底，但 token subject 就有 username，缺透传链路
4. 无删除入口 —— 备份失败 / 不需要的历史记录只能等 `trimOldRecords` 自动清，无法手动删

## 新增

### 后端

- `BackupService.deleteBackupRecord(Long id, HttpServletRequest)`
  - 业务规则：PENDING / RUNNING → 拒绝（`BACKUP_RECORD_RUNNING(3002)`）；SUCCESS → 先 `deleteGitHubRelease(tag)`（best-effort，失败 WARN 不回滚 db）→ 再删 db 行；FAILED → 直接删 db 行
  - 与 `trimOldRecords` 共享 `deleteGitHubRelease()`，命令构造零分叉
  - 写 INFO 操作日志（含 operator username）便于审计
- `BackupController.delete(@PathVariable Long id)` — `DELETE /api/v1/admin/backup/{id}`
- `ResultCode.BACKUP_RECORD_RUNNING(3002, "备份任务进行中，无法删除")`
- `GlobalExceptionHandler.handleBusiness` 业务异常 message 拼接 traceId 后缀（沿用 handleAny 已有的 FR-4.3 行为）—— 之前 5xx 才拼，业务错 BACKUP_CONFLICT 等 toast 不带 traceId，前端排查不方便

### 前端

- `pages/admin/backup.vue` 整体重写（v4.2.0 当天上得急，结构跟 posts.vue / comments.vue 差太多）
  - 页头、按钮、表格、分页、操作列全部对齐 admin 设计系统（`.page-head` / `.btn-new` / `.card` / `.table` / `.table-wrap` / `.row-actions` / `.admin-pagination`）
  - `db 大小` / `uploads 大小` 列合并成 `db / uploads`（同行两行），省横向空间
  - 标签 tag 加"复制"按钮（`navigator.clipboard.writeText` + toast 反馈），省得手动选中
  - 操作列：复制 tag / 删除
- 失败 toast 自动提取 traceId
  - `formatError(e, fallback)` helper：优先用 message 里已有的 `traceId=xxx` 后缀（GlobalExceptionHandler 已拼）；否则从响应头 `X-Trace-Id` 兜底抽
  - 所有 `catch` 块统一走 `formatError`
- 删除按钮
  - PENDING / RUNNING：禁用 + tooltip"备份进行中，无法删除"（第一道防线）
  - SUCCESS：`$dialog.prompt` 要求输入 `DELETE` 字样才放行（防误删）
  - FAILED：普通 `$dialog.confirm`
- 触发备份按钮也加 `$dialog.confirm` 二次确认（之前是无脑触发）

## 改动

### 后端

- `AuthContext` 加 `ATTR_USERNAME` 常量 + `set(request, uid, deviceId, username)` / `username(request)` 方法
- `AdminAuthFilter.doFilterInternal` 从 `claims.getSubject()` 取 username 写入 attribute
  - token 签发时 `setSubject(username)` 已存在（`JwtUtil.generate`），零额外 IO
- `BackupService.resolveOperatorName` 优先用 `AuthContext.username()`，兜底 `"uid:xxx"`
- `AdminAuthFilter` 鉴权通过日志 `log.info("admin 鉴权通过：...")` 增加 `username={}` 字段（便于安全审计）
- 鉴权拒绝日志等不变

### 审查后修复（v4.2.1 polish 同一 commit 内）

实现期间发现 2 处真问题，**一并修复**：

1. **traceId 在 admin 鉴权拒绝响应里缺失**（Issue 3.1）
   - `AdminAuthFilter.writeUnauthorized` / `IpRateLimitFilter.writeTooManyRequests` 直接 `response.getWriter().write(...)`，
     不走 GlobalExceptionHandler，response message 也不带 traceId。
     全 admin 页 token 过期 / 设备被吊销 / IP 被封禁的 toast 都看不到 traceId，用户无法定位日志。
   - **修复**：新增 `com.blog.common.web.TraceIdUtil.withTraceId(message)` helper，从 MDC 读 traceId 拼后缀
     （与 GlobalExceptionHandler 现有行为完全一致）。`AdminAuthFilter` / `IpRateLimitFilter` / `GlobalExceptionHandler`
     三处共用同一 helper，避免三份重复逻辑。
   - 顺手把 `GlobalExceptionHandler.handleBusiness` 和 `handleAny` 也改成调用 helper，去掉重复代码。

2. **删除最后一条跳到空页**（Issue 4.6）
   - backup.vue `handleDelete` 删除后直接 `await fetchList()`，如果当前页是 page>1 且删完刚好空，
     用户会看到空白页 + 必须手动点上一页。
   - **修复**：删后判断 `list.value.length <= 1 && page.value > 1` → 自动回退到上一页。
