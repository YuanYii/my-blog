## 1. 项目概述

### 1.1 目标

搭建一个**前后端分离**的个人博客系统，支持 PC 与移动端响应式访问，提供文章发布、分类标签、评论、检索等基础能力。

### 1.2 范围

**包含**（首期交付）：
- 文章发布与管理（Markdown 编辑，前端 marked + DOMPurify 实时预览）
- 分类、标签、归档、热门标签
- 评论（树形嵌套回复，游客可评论）
- 后台管理（单管理员）
- 响应式前端（PC / 平板 / 移动端）
- 基础 SEO + RSS 订阅
- 文件上传（封面图 + Markdown 内嵌图片，本地存储）
- 设置中心：6 个 tab（个人资料 / 站点信息 / 主题外观 / 社交账号 / 偏好设置 / 高级）
  - 注：实际实现 6 tab 内容是 个人资料/站点信息/主题外观/社交账号/偏好设置/高级（与"不包含"中的数据导入/导出、媒体库一起移入 Roadmap）
- 后台仪表盘：KPI 卡片、访问趋势、分类分布、待办清单、站点状态

**不包含**（首期不做，移入 Roadmap）：
- 多用户体系
- 付费阅读 / 会员
- 实时通知 / WebSocket
- 多语言
- 邮件通知（已从偏好设置移除）
- 全文检索（首期用 MySQL `LIKE` 兜底）
- 数据导入 / 导出（首期页面已实现但功能后置）
- 媒体库管理（已从 sidebar 移除，图片直接上传）
- 访问统计埋点（首期只统计文章阅读数，仪表盘展示**昨天**的数据）

### 1.3 非功能性目标

| 指标 | 目标 |
|------|------|
| 首屏加载 | ≤ 2s（4G 网络） |
| 移动端可用性 | 主流机型（iOS 14+ / Android 9+）流畅 |
| SEO | 主要页面被 Google / 百度正常收录 |
| 可维护性 | 新人 1 天内能跑起来 |
| API 文档 | springdoc-openapi 自动生成，无需手写 |

## 2. 技术选型

### 2.1 前端

| 类别 | 选型 | 版本 | 理由 |
|------|------|------|------|
| 框架 | Nuxt 3 | ^3.13 | 基于 Vue 3，原生支持 SSG/SSR，SEO 友好 |
| 包管理 | pnpm | ^9 | 安装快、磁盘占用小 |
| 样式 | Tailwind CSS | ^3.4 | 响应式类写起来直接，无需 CSS-in-JS |
| 状态管理 | Pinia | ^2.2 | Nuxt 3 官方推荐 |
| Markdown 渲染 | **marked + DOMPurify** | ^14 / ^3.1 | **纯前端**渲染，后端只存原文 |
| 代码高亮 | Shiki | ^1 | 美观，支持双主题（亮/暗） |
| HTTP | ofetch | ^1.4 | Nuxt 3 内置，无需 axios |
| 类型 | TypeScript | ^5.5 | 全量类型化 |

> **关键决策**：Markdown 渲染放前端。后端只存 `content_md` 原文，详情接口返回原文，前端用 marked 解析 + DOMPurify 清洗 XSS。
> **优点**：后端零渲染开销、CDN 友好、前端可控。**缺点**：包大（marked+DOMPurify 约 80KB）。

> **备选**：若团队更熟 React，可替换为 Next.js 14（App Router），架构不变。

### 2.2 后端

| 类别 | 选型 | 版本 | 理由 |
|------|------|------|------|
| **构建工具** | **Maven** | 3.9.x | Java 生态主流 |
| 框架 | Spring Boot | 3.3.5 | 主流、生态成熟 |
| **JDK** | **Java** | **21 LTS** | 长期支持，性能优于 17 |
| ORM | MyBatis-Plus | 3.5.9 | 比 JPA 灵活，含代码生成器 |
| 数据库 | MySQL | 8.0 | 稳，工具链完善 |
| 缓存 | Redis | 7.x | 缓存首页、热点文章、计数器 |
| 鉴权 | JJWT | 0.12.6 | 前后端分离标准方案 |
| 工具库 | Hutool | 5.8.x | 减少样板代码 |
| 简化代码 | Lombok | 1.18.x | Getter/Setter/Builder |
| **API 文档** | **springdoc-openapi** | **2.6.0** | Swagger 3 官方推荐（替代 Knife4j） |

> **不引入 MapStruct**：项目规模小，MyBatis-Plus 自带的 `BeanUtil` 足够。
> **不引入 Spring Security**：用 Spring Filter 拦截 + 手动 JWT 解析，配置更轻量。

### 2.3 基础设施

| 类别 | 选型 | 备注 |
|------|------|------|
| 容器化 | Docker + Docker Compose | 本地与生产一致 |
| 反向代理 | Nginx | 前端静态资源 + API 反代 |
| CI/CD | GitHub Actions | 自动化测试 + 镜像构建 |
| 监控 | Spring Boot Actuator + 简易日志 | 首期不上 Prometheus |
| **文件存储** | **本地磁盘** | 首期 `/data/uploads/`，后期可换 OSS |

### 3.2 分层架构（后端）

```
Controller  ── 接收请求、参数校验、返回统一响应
    ↓
Service     ── 业务逻辑、事务控制、缓存策略
    ↓
Mapper      ── 数据库访问（MyBatis-Plus）
    ↓
Database
```

辅助层：
- `common/`：统一响应 `Result`、状态码 `ResultCode`、业务异常 `BusinessException`、全局异常处理 `GlobalExceptionHandler`、分页对象 `PageRequest` / `PageResult`
- `config/`：CORS、MyBatis-Plus 分页插件、springdoc-openapi
- `jwt/`：JWT 工具 `JwtUtil`、过滤器 `JwtAuthenticationFilter`、配置 `JwtConfig`（不引入 Spring Security）
- `entity/`：数据库实体（5 张表）
- `dto/` / `vo/`：入参 / 出参对象
- `schedule/`：定时任务（仪表盘昨日数据聚合）

### 4.2 响应式方案

**断点**（Tailwind 默认）：

| 断点 | 宽度 | 设备 |
|------|------|------|
| 默认 | < 640px | 移动端 |
| `sm` | ≥ 640px | 大屏手机 |
| `md` | ≥ 768px | 平板 |
| `lg` | ≥ 1024px | PC |
| `xl` | ≥ 1280px | 大屏 PC |

**布局原则**：
- 移动端：单列、全宽、`px-4`
- 平板：单列、限制宽度、`px-8`
- PC：居中、最大宽度 768px（阅读体验最佳）

**导航**：
- PC 前台：横向 NavBar
- PC 后台：左侧 Sidebar + 顶部 Header
- 移动端：汉堡菜单 → 抽屉式

### 4.3 主题与样式

- **主色**：墨绿 `#2f6f5e`（设计稿实际取值）
- **辅色**：焦糖橙 `#c97b3f`（点缀）
- **字体**：
  - 中文标题：`Noto Serif SC`（衬线，庄重）
  - 英文标题：`DM Serif Display`（衬线，识别度高）
  - 正文中英文：`Outfit`（无衬线，屏读友好）
  - 代码：`JetBrains Mono`（等宽，技术感）
- **暗色模式**：通过 `html.dark` 切换，所有颜色用 CSS 变量，亮/暗模式自适应

#### 5.2.2 核心表 DDL

```sql
-- 文章
CREATE TABLE article (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  title         VARCHAR(200) NOT NULL,
  slug          VARCHAR(200) UNIQUE NOT NULL,
  summary       VARCHAR(500),
  content_md    MEDIUMTEXT NOT NULL,
  cover_url     VARCHAR(500),
  status        TINYINT DEFAULT 0 COMMENT '0-草稿 1-已发布 2-已归档',
  view_count    INT DEFAULT 0,
  category_id   BIGINT,
  published_at  DATETIME,
  created_at    DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at    DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  deleted       TINYINT DEFAULT 0 COMMENT '逻辑删除',
  INDEX idx_status_published (status, published_at DESC),
  INDEX idx_category (category_id)
);

-- 分类
CREATE TABLE category (
  id       BIGINT PRIMARY KEY AUTO_INCREMENT,
  name     VARCHAR(50) NOT NULL,
  slug     VARCHAR(50) UNIQUE NOT NULL,
  sort     INT DEFAULT 0,
  visible  TINYINT DEFAULT 1 COMMENT '0-隐藏 1-显示',
```

#### 5.2.3 设置与鉴权相关表（v2.1 / v2.2 新增）

```sql
-- 对应 docs/sql/migration-site-settings.sql
CREATE TABLE site_settings (

-- 设备白名单（v2.2）：管理端登录设备需审批，token 绑定 device_id
-- 对应 docs/sql/migrations/20260607_device_whitelist.sql
CREATE TABLE admin_device (

-- API 路由白名单（v2.2）：AdminAuthFilter 据此判定放行/鉴权，最长前缀优先匹配
-- 对应 docs/sql/blog.sql + docs/sql/migrations/20260612_admin_subpaths.sql
CREATE TABLE api_whitelist (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  path_prefix VARCHAR(200) NOT NULL COMMENT 'API 路径前缀，例 /api/v1/articles',
```

> **鉴权设计要点**：`AdminAuthFilter` 不再硬编码公开路径，而是查 `api_whitelist` 做**最长前缀匹配**。`public` 前缀的 GET 匿名放行；写方法（POST/PUT/DELETE）默认要求鉴权，仅 `POST /auth/login` 与 `POST /comments` 例外（2026-06-12 修复匿名写漏洞）。同时 token 的 `deviceId` claim 必须与请求头 `X-Device-Id` 一致，且该设备在 `admin_device` 中为 `approved`。

### 5.3 关键流程

#### 5.3.1 发布文章

```
1. 管理员在后台填写 Markdown → 提交
2. 后端：
   a. @Valid 校验参数
   b. 写入 article 表（status=1, published_at=now）
   c. 写 article_tag 关联
   d. 删除该文章相关 Redis 缓存
3. 返回成功 → 前端提示并跳转
```

> **注意**：后端**不渲染** HTML，只存 `content_md` 原文。前端用 marked 渲染。

#### 5.3.2 获取文章详情

> ⚠️ **计划中（尚未落地）**：以下流程中的「Redis 缓存文章详情」与「`POST /api/v1/articles/{slug}/view` 异步上报阅读量」当前**均未实现**。实际代码中 `GET /articles/{slug}` 直接查库返回，无 Redis 文章缓存，也没有 `/view` 端点（目前仅 `site_settings` 接入了 Redis 5min 缓存）。保留本设计作为后续目标。

```
1. 前端 GET /api/v1/articles/{slug}
2. 后端：
   a. 查 Redis 缓存：key=`article:{slug}`
   b. 命中 → 直接返回 content_md
   c. 未命中 → 查 DB → 写缓存（TTL 1h） → 返回
3. 前端拿到 content_md → marked 解析 + DOMPurify 清洗 → 渲染
4. 异步（POST /api/v1/articles/{slug}/view）：
   a. Redis INCR article:view:{id}
   b. 写 article_view_log（按天聚合）
```

#### 5.3.3 评论提交

```
1. 游客提交评论（昵称、邮箱、URL、内容）
2. 后端：
   a. @Valid 校验内容
   b. 敏感词过滤（首期用简单词表，后期可换 DFA）
   c. 写 comment 表（默认 status=0 待审）
   d. 清除文章评论缓存
3. 管理员后台审核（通过/屏蔽/删除）
4. 已通过的评论对外可见
```

#### 5.3.4 仪表盘数据聚合

```
每日凌晨 02:00 定时任务：
  1. 查询 article_view_log，按 article_id 分组，统计「昨天」的 view_count 增量
  2. 写入 article.view_count（累加）
  3. 计算「昨天」的 KPI：
     - 文章 PV 总数 = SUM(article.view_count 增量)
     - 新发布文章数 = COUNT(article WHERE published_at BETWEEN 昨天 00:00 - 23:59)
     - 待审评论数 = COUNT(comment WHERE status=0)
     - 总字数 = SUM(article.content_md.length)
  4. 写入 Redis dashboard:yesterday:{metric}

仪表盘请求：
  GET /api/v1/admin/dashboard
  1. 读 Redis dashboard:yesterday:* 拿到昨日数据
  2. 查 DB 拿到「总文章数」「已发布」「草稿」（实时）
  3. 查 DB 拿到「近 30 天文章阅读趋势」（按天聚合）
  4. 组装 VO 返回
```

### 5.5 鉴权

- **前端门户**：完全匿名，无需登录
- **后台管理**：
  - `POST /api/v1/auth/login` 接收 username + password
  - BCrypt 校验密码（Spring Security Crypto 模块）
  - 校验成功后签发 JWT（有效期 7 天，HS256，secret 256 bit）
  - 后续请求带 `Authorization: Bearer <token>` 与 `X-Device-Id: <设备指纹>`（均放在 Header）
  - 自实现 `AdminAuthFilter`（`com.blog.common.security`）拦截 → 查 `api_whitelist` 最长前缀匹配判定放行/鉴权 → 解析 token（不用 Spring Security）
  - 设备校验：token 的 `deviceId` claim 必须与 `X-Device-Id` 一致，且该设备在 `admin_device` 为 `approved`（待授权 2001 / 已吊销 2002）
  - 角色控制：JWT claims 含 `role`，admin 接口手动校验
- **刷新策略**（首期简化）：Token 7 天有效，过期后重新登录。后期可加 Refresh Token。

**鉴权规则**：
- 放行/鉴权由 `AdminAuthFilter`（`com.blog.common.security`）按 `api_whitelist` 表**最长前缀匹配**判定，不再硬编码路径
- `public` 前缀：GET/HEAD 匿名放行；写方法（POST/PUT/DELETE/PATCH）默认要求 token，仅 `POST /auth/login` 与 `POST /comments` 例外
- `admin` 前缀：一律要求 token + 设备校验（`X-Device-Id` 须为 `approved` 且与 token claim 一致）
- 缺少 / 无效 / 过期 token 返回 401；设备未授权 2001 / 已吊销 2002

**字段命名**：所有响应字段统一 **camelCase**（如 `articleId`/`createdAt`/`userId`），即使数据库列是 `snake_case`，SQL 里用 `AS` 别名映射。

**错误码规范**（与 `com.blog.common.ResultCode` 一致）：

| code | 含义 | code | 含义 |
|------|------|------|------|
| 200 | 成功 | 1000 | 业务异常 |
| 400 | 参数错误 | 1001 | 文章不存在 |
| 401 | 未登录 / token 无效 | 1002 | 分类不存在 |
| 403 | 无权限 | 1003 | 标签不存在 |
| 404 | 资源不存在 | 1004 | 评论不存在 |
| 405 | 请求方法不允许 | 1005 | 用户不存在 |
| 500 | 服务器内部错误 | 1006 | 用户名或密码错误 |
| 2001 | 设备未授权 | 1007 | Token 无效或已过期 |
| 2002 | 设备已吊销 | 2003 | 不能吊销当前登录设备 |

### 7.3 Docker Compose（本地 & 自托管）

```yaml
version: '3.8'
services:
  mysql:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_PASS}
      MYSQL_DATABASE: blog
    volumes:
      - mysql_data:/var/lib/mysql
    ports:
      - "3306:3306"

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"

  backend:
    build: ./backend
    depends_on: [mysql, redis]
    environment:
      SPRING_PROFILES_ACTIVE: prod
      DB_URL: jdbc:mysql://mysql:3306/blog
      DB_USER: root
      DB_PASS: ${DB_PASS}
      REDIS_HOST: redis
    volumes:
      - ./uploads:/data/uploads
    ports:
      - "8080:8080"

  nginx:
    image: nginx:alpine
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf
      - ./uploads:/data/uploads
    ports:
      - "80:80"
      - "443:443"
    depends_on: [backend]

volumes:
  mysql_data:
```

`nginx.conf` 关键配置：

```nginx
server {
    listen 80;
    server_name yourname.com;

    # 前端静态资源
    location / {
        root /var/www/blog-frontend;
        try_files $uri $uri/ /index.html;
    }

    # 后端 API
    location /api/ {
        proxy_pass http://backend:8080;
    }

    # 上传文件静态服务
    location /uploads/ {
        alias /data/uploads/;
        expires 30d;
    }
}
```
