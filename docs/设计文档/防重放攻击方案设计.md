# 防重放攻击方案设计

> 状态：**待实现**（设计稿，2026-06-07）
> 推荐组合：admin 写请求 / 60s 时间窗 / Redis 存 nonce / 不签名

## 背景

当前项目已有的鉴权防御链：

| 攻击场景 | 防护层 |
|----------|--------|
| 暴力破解密码 | 登录限流（5 次/分钟，in-memory） |
| Token 跨设备使用 | JWT claim deviceId |
| Token 长期有效 | 24h 过期 |
| 新设备登录 | 设备白名单 |
| 未授权设备 | AdminAuthFilter deviceId 校验 |
| XSS 偷 token | DOMPurify 净化 |

**缺失环节**：Token 拿到后**重发同一请求**——token + body 被截获，原样重发仍能成功。

## 方案：时间戳 + Nonce 双重防重放

### 核心设计

| 层 | 机制 |
|---|------|
| **客户端** | 所有 POST/PUT/DELETE 请求自动加 `X-Timestamp`（秒级 epoch）+ `X-Nonce`（UUIDv4 ≥16 字符） |
| **服务端** | 拦截 admin/** 的写请求：① 校验 timestamp 偏离 < 60s；② Redis 存 nonce，TTL=120s，重放则拒 |
| **豁免** | GET 请求（幂等）+ login（无 token）+ health |
| **降级** | Redis 不可用时放行（与登录限流一致） |

### 两道防线

- **时间戳**：防"长期重放"——截获后必须在 60s 内重发，窗口短
- **nonce**：防"短期重放"——60s 内重发直接拒（一次性）
- **叠加效果**：攻击者**只可能在 60s 内、且只发 1 次**

### 关键决策记录

| 决策 | 选择 | 备选 |
|------|------|------|
| 防护范围 | 仅 admin 写请求（POST/PUT/DELETE） | 全 admin / 全站写 |
| 时间窗 | 60s | 30s（严）/ 300s（宽） |
| nonce 存储 | Redis | in-memory |
| 请求签名 | 不加 | HMAC（抗篡改） |

## 实施成本

| 文件 | 改动 | 行数 |

## 待实现细节

### 1. AntiReplayService（Redis nonce 存储）

```java
@Service
public class AntiReplayService {
    private static final String NONCE_KEY_PREFIX = "auth:replay:nonce:";
    private static final int NONCE_TTL_SECONDS = 120;

    /** 检查并记录 nonce：true = 首次出现（合法），false = 已存在（重放） */
    public boolean checkAndRecord(String nonce) {
        try (Jedis j = RedisDS.create().getJedis()) {
            String key = NONCE_KEY_PREFIX + nonce;
            String result = j.set(key, "1", SetParams.setEx(NONCE_TTL_SECONDS));
            return "OK".equals(result);  // SETNX 语义
        } catch (Exception e) {
            return true;  // Redis 不可用放行
        }
    }
}
```

### 2. AntiReplayFilter

```java
@Component
public class AntiReplayFilter extends OncePerRequestFilter {
    private static final long MAX_TIMESTAMP_DRIFT = 60;  // 秒
    private final AntiReplayService antiReplayService;

    @Override
    protected boolean doFilterInternal(HttpServletRequest req, HttpServletResponse res, FilterChain chain) {
        // 1) 只对 admin 写请求生效
        String path = req.getRequestURI();
        if (!path.contains("/admin/")) return true;
        String method = req.getMethod();
        if (!("POST".equals(method) || "PUT".equals(method) || "DELETE".equals(method))) return true;

        // 2) 校验 timestamp
        String ts = req.getHeader("X-Timestamp");
        String nonce = req.getHeader("X-Nonce");
        if (ts == null || nonce == null) {
            writeError(res, 400, "缺少防重放头");
            return false;
        }
        long now = Instant.now().getEpochSecond();
        long requestTs;
        try { requestTs = Long.parseLong(ts); } catch (Exception e) { writeError(res, 400, "时间戳格式错误"); return false; }
        if (Math.abs(now - requestTs) > MAX_TIMESTAMP_DRIFT) {
            writeError(res, 401, "请求时间戳过期，请重试");
            return false;
        }

        // 3) 校验 nonce（一次性）
        if (!antiReplayService.checkAndRecord(nonce)) {
            writeError(res, 401, "请求重复或 nonce 已被使用");
            return false;
        }

        return true;
    }
}
```

### 3. 前端 useApi 自动加头

```ts
const request = <T = any>(path: string, options: any = {}): Promise<T> => {
    const method = options.method || 'GET'
    const isWrite = method === 'POST' || method === 'PUT' || method === 'DELETE' || method === 'PATCH'
    const headers: Record<string, string> = {
        'Content-Type': 'application/json',
        ...(options.headers || {})
    }
    // 写请求自动加防重放头
    if (isWrite) {
        headers['X-Timestamp'] = String(Math.floor(Date.now() / 1000))
        headers['X-Nonce'] = crypto.randomUUID()
    }
    // ... 原有逻辑
}
```

## 验收用例

1. **正常请求**：POST 带 timestamp + nonce → 通过
2. **时间戳过期**：timestamp 偏离 > 60s → 401
3. **重放**：同一 timestamp + nonce 第二次发 → 401
4. **缺少头**：不带头 → 400
5. **GET 请求**：不带防重放头 → 通过（GET 豁免）
6. **降级**：Redis 挂 → 全部放行（记录 ERROR 日志）

## 风险与权衡

- **客户端时钟偏差**：容忍 ±60s，误杀概率低
- **Redis 不可用**：降级放行（保护可用性，不引入单点失败）
- **多实例部署**：用 Redis 共享 nonce 状态
- **GET 请求不防**：GET 是幂等的，重放无副作用，省资源
- **签名不强制**：HTTPS + nonce + timestamp 已构成有效防护；签名需要客户端 secret 传输，复杂度高
