# 博客数据备份方案设计

> 需求 ID: REQ-BACKUP-2026-06-20
> 状态: v1.0 设计稿（已实现，2026-06-20）
> 关联 changelog: `docs/changelogs/2026-06-20-v4.2.0-data-backup.md`

## 1. 目标与约束

**目标**：admin 后台新增"数据备份"菜单，点击一键备份生产服务器的**全量数据**（SQLite db + 上传文件），加密后上传到**独立的 GitHub 备份仓库**的 Release，可随时从 Release 拉回恢复。

**约束**：

1. **加密链路复用** v4.0.0 加密数据迁移的 AES-256-CBC + PBKDF2 100k 链路（`sqlite-export.sh` / `sqlite-import.sh`），不引入新加密算法/新依赖
2. **GitHub 通道复用** `publish-release.sh` 的 `gh release` 上传模式（也支持 `curl + BACKUP_GITHUB_TOKEN` 兜底，不强依赖 gh CLI）
3. **不能停服务**：备份期间后端正常服务（SQLite 的 `.backup` 走 online backup，WAL 已开）
4. **不能泄漏明文**：所有 .gz / .tar 文件在落盘后**立即**加密成 `.enc`，明文中转目录定时清空
5. **不引入新的后台任务框架**：JDK `ProcessBuilder` + 数据库状态字段就够（1 个 backup_record 表）
6. **admin 鉴权 + 操作日志**：按 AGENTS.md §4.8 P0 安全类，备份成功/失败/无权限都打 INFO/WARN，禁打密码/secret

## 2. 备份内容

| 数据 | 位置 | 备份方式 | 加密 |
|---|---|---|---|
| SQLite db（含全部业务表） | `${SQLITE_PATH}`（默认 `/opt/myblog/blog.db`） | 调 `sqlite-export.sh` 产出加密 dump | 已有 `.enc` |
| 上传文件（图片/附件） | `${UPLOAD_DIR}`（默认 `/opt/myblog/uploads`） | `tar czf` 打包 → `openssl enc -aes-256-cbc` | 新增 `.enc` |
| 元数据 | — | `manifest.json`（db 行数/uploads 文件数/SHA256/时间） | **明文**（仅元数据，不含数据） |

**不备份**：

- 日志（`/opt/myblog/logs/`）：日志由 logrotate 管理，备份不归此脚本管
- `frontend/.output/public/`：可从代码仓 `nuxt generate` 重建，没必要占备份体积
- `backups/` 自身（避免套娃）

## 4. 加密策略

**两层加密**：

1. db 内部：复用 `sqlite-export.sh` 的 AES-256-CBC + PBKDF2 100k（`openssl enc -aes-256-cbc -pbkdf2 -iter 100000`）
2. uploads 打包：同样 AES-256-CBC + PBKDF2 100k（保持密码一致，一次输入恢复全部数据）

**密码管理**：

- 密码从 `/etc/myblog/myblog.env` 的 `BACKUP_ENCRYPTION_PASSWORD` 读
- **绝不**写到日志、绝不返回给前端、绝不入 db
- 前端发起备份请求时，**不**需要传密码——后端从 env 读，admin 自己改 env 即可轮换密码

**明文中转清理**：

- 脚本运行期间的明文（未加密的 tar、sqlite dump）放在 `$BACKUP_STAGE_DIR`（默认 `/tmp/blog-backup-stage`）
- 脚本**任何退出路径**（成功/失败/被 kill）都先 `trap` 清理 → 再 `exit`
- `/tmp` 重启自动清，无需额外逻辑

## 5. 触发与状态

### 5.1 API 契约

| 方法 | 路径 | 用途 | 鉴权 |
|---|---|---|---|
| POST | `/api/v1/admin/backup/run` | 触发备份（异步） | admin |
| GET  | `/api/v1/admin/backup/list` | 历史列表 | admin |
| GET  | `/api/v1/admin/backup/{id}` | 单条详情 + 状态 | admin |

**POST /run 响应**：

```json
{
  "code": 200,
  "data": {
    "id": 42,
    "status": "PENDING",
    "message": "备份任务已创建，异步执行中"
  }
}
```

**GET /{id} 响应（SUCCESS）**：

```json
{
  "code": 200,
  "data": {
    "id": 42,
    "status": "SUCCESS",
    "tag": "backup-20260620-153012",
    "startedAt": "2026-06-20T15:30:12+08:00",
    "finishedAt": "2026-06-20T15:32:48+08:00",
    "durationSec": 156,
    "dbSize": 5242880,
    "uploadsSize": 104857600,
    "assetCount": 4,
    "assetUrls": [
      "https://github.com/.../blog-encrypted.sql.gz.enc",
      "https://github.com/.../uploads-encrypted.tar.gz.enc",
      "https://github.com/.../manifest.json",
      "https://github.com/.../SHA256SUMS"
    ]
  }
}
```

**GET /{id} 响应（FAILED）**：

```json
{
  "code": 200,
  "data": {
    "id": 42,
    "status": "FAILED",
    "errorStage": "UPLOAD",
    "errorMessage": "gh release create failed: 401 Unauthorized"
  }
}
```

### 5.2 业务码

复用现有码表：

| code | 含义 |
|---|---|
| 200 | 成功 |
| 401 | 未登录 / token 无效 |
| 403 | 无权限（admin 鉴权失败） |
| 500 | 服务器错误 |
| 3001 | 备份任务冲突（已有 RUNNING 中的任务） |

### 5.3 状态机

```
PENDING ─→ RUNNING ─→ SUCCESS
              │
              └────→ FAILED
```

- 任何时刻只允许 1 个 RUNNING（防并发触发把 SQLite 锁死/把 uploads 拉两遍）
- 检测到 RUNNING 已有 → POST /run 返回 3001

## 6. 数据库变更

新增 1 张表 `backup_record`：

```sql
CREATE TABLE backup_record (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    tag             TEXT,                          -- 备份 tag（成功后才填）
    status          TEXT NOT NULL,                 -- PENDING/RUNNING/SUCCESS/FAILED
    started_at      DATETIME NOT NULL,
    finished_at     DATETIME,                      -- 结束时间
    db_size         INTEGER DEFAULT 0,             -- db dump 大小（字节）
    uploads_size    INTEGER DEFAULT 0,             -- uploads tar 大小（字节）
    asset_count     INTEGER DEFAULT 0,
    asset_urls      TEXT,                          -- JSON 数组
    manifest_json   TEXT,                          -- 备份清单
    error_stage     TEXT,                          -- 失败阶段: DUMP/PACK/UPLOAD
    error_message   TEXT,                          -- 失败信息
    operator_id     INTEGER,                       -- 触发人
    operator_name   TEXT
);
CREATE INDEX idx_backup_record_started_at ON backup_record(started_at DESC);
CREATE INDEX idx_backup_record_status ON backup_record(status);
```

**v2.6.0 整合到 `docs/sql/schema-sqlite.sql`**：v4.2.0 完成后，下次整合到主 schema 时加进去。

**字段命名规范**：snake_case + 末尾时间戳 `_at` / 末尾布尔 `_flag`（按 AGENTS.md §7）。

## 7. 部署集成

### 7.1 脚本位置

`blog-backup.sh` 跟着 deploy-server.sh 一起部署到 `/opt/myblog/scripts/blog-backup.sh`。

### 7.2 环境变量（加到 `deploy-server.env.example`）

```bash
# === 备份 ===
# 加密密码（**绝不** commit / 写到日志）
BACKUP_ENCRYPTION_PASSWORD=REPLACE_ME_WITH_STRONG_RANDOM
# GitHub 备份仓库（独立于 my-blog-prov）
GITHUB_BACKUP_REPO=yourname/my-blog-backup
# GitHub PAT（需要 repo 权限，**只**给 my-blog-backup 用）
# 2026-06-20 v4.2.0 重命名: GITHUB_TOKEN → BACKUP_GITHUB_TOKEN
# 发布链路的 GITHUB_TOKEN 走 deploy.env / CI 临时注入, **不**进这个 env
# 强烈建议用 Fine-grained PAT, 只勾 my-blog-backup 仓库的 Contents: Read and write
BACKUP_GITHUB_TOKEN=REPLACE_ME
# 备份明文中转目录（脚本退出 trap 清理）
BACKUP_STAGE_DIR=/tmp/blog-backup-stage
# 备份脚本保留份数（SUCCESS 状态保留最近 N 条，旧的删 db 记录）
BACKUP_KEEP_RECORDS=30
```

### 7.3 cron（可选，本期**不**内置）

本次只做"点击菜单触发"。cron / systemd timer 留作后续 OPT 项，避免越界。

## 9. 安全与日志

按 AGENTS.md §4.8：

| 事件 | 级别 | 字段 |
|---|---|---|
| 备份启动 | INFO | operator_id, request_ip, requested_at |
| 备份成功 | INFO | record_id, tag, size, duration_sec |
| 备份失败 | WARN | record_id, error_stage, error_message |
| 非 admin 触发 | WARN | request_ip, uid（被拒原因） |
| 已有 RUNNING 任务 | WARN | record_id（冲突的现有任务） |
| 脚本被 kill | WARN | record_id, signal |

**禁打**：

- 密码明文 / `BACKUP_ENCRYPTION_PASSWORD` 值
- GitHub token
- 上传文件内容

## 11. 风险与限制

| 风险 | 缓解 |
|---|---|
| 备份期间 SQLite 写阻塞 | 用 `sqlite3 .backup`（online backup，WAL 已开），不直接 copy |
| uploads 体积大（GB 级）| tar 压缩 + 流式加密，磁盘中转不落明文压缩包；明文只走 pipe |
| GitHub Release 单文件 2GB 上限 | uploads 切分警告：>1.5GB 时 WARN（不让用户卡死在 release 阶段） |
| Token 泄漏 | PAT 走 /etc/myblog/myblog.env（chmod 600），不写到代码 / db / 日志 |
| 备份 repo 被公开 | 用 private repo + 强密码 + 文档建议 |
| 误触 | 二次确认对话框 + 状态机并发保护 |
