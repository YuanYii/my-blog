# my-blog 阿里云部署方案（v2.0）

**项目**：vibeP/my-blog **v2.7.0**（v2.6.0 SQLite 改造 + v2.7.0 前端全静态化）
**最近更新**：2026-06-17
**目标**：个人博客公网访问 + HTTPS + 可控成本（**v2.6+ 月成本降到 ~¥30**）
**决策组合**：
- **A1** 境外免备案（阿里云**香港/新加坡轻量 ECS**）
- **B2-改** 数据库**SQLite 一文件**（v2.6.0 起，MySQL 降级为可选 profile）
- **B3-改** 缓存 / 前端服务 / 后端 jar 全部走 **apt 系统服务**（v2.6+ 无 docker）
- **C3** 文件**本地存储**（`/data/uploads/` 持久化到 ECS 磁盘）
- **D5-改** 部署走 **`scripts/deploy-sqlite.sh`**（v2.6.0 一键脚本） + **`scripts/rebuild-static.sh`**（v2.7.0 每日 cron）
- **D6-改** 前端走 **`nuxt generate` 全静态 + nginx:alpine serve**（v2.7.0，省 150-250MB 内存）

> **2026-06-17 v2.0 重大更新**：v2.6.0 砍掉 MySQL/Docker Compose，改用 SQLite + apt 装服务；v2.7.0 砍掉 Nuxt SSR node 容器，改用全静态文件 + nginx:alpine serve。**月成本从 ~¥60 降到 ~¥30**，运维复杂度大幅下降。
> 详细 changelog 见 `docs/changelogs/2026-06-17-v2.6.0-sqlite-migration.md` + `docs/changelogs/2026-06-17-v2.7.0-nuxt-static.md`。

## 二、整体架构

> **2026-06-17 v2.0 更新**：v2.5.0 之前是"5 容器 Docker Compose"（mysql / redis / backend / frontend / web）；**v2.6.0 起改为"无 docker 1C2G + SQLite"**（apt 装 redis-server + nginx + openjdk-8-jdk + sqlite3）；**v2.7.0 起前端改为"全静态文件 + nginx:alpine serve"**，无 node 运行时。

**当前架构（v2.6.0 + v2.7.0）**：

```
                  ┌─ 阿里云 DNS ─────┐
                  │   (yourname.com) │
                  └─────────┬────────┘
                            │ (公网)
                  ┌─────────▼────────┐
                  │ 阿里云 ECS 香港   │
                  │  轻量 1C2G       │   ← v2.6+ 从 2C2G 降到 1C2G
                  │ ┌──────────────┐ │
                  │ │ nginx (apt)  │ │
                  │ │ :80 → :443   │ │
                  │ │ / 静态 serve │ │   ← v2.7.0 配套 /var/www/blog/
                  │ │ /api/* :8080 │ │
                  │ │ /uploads/*   │ │
                  │ └──────┬───────┘ │
                  │ ┌──────▼───────┐ │
                  │ │ Spring Boot  │ │   ← systemd 托管（myblog.service）
                  │ │ :8080 jar    │ │     JVM 128-384MB
                  │ └──────┬───────┘ │
                  │ ┌──────▼───────┐ │
                  │ │ SQLite db    │ │   ← v2.6+ 替代 MySQL
                  │ │ /opt/myblog/ │ │     一文件 0 内存
                  │ │  blog.db     │ │
                  │ ├──────────────┤ │
                  │ │ redis-server │ │   ← apt 装系统服务
                  │ │ :6379        │ │
                  │ └──────────────┘ │
                  │ /data/uploads/    │  ← 文件本地存储
                  └───────────────────┘

# 每日凌晨 3 点 cron：
scripts/rebuild-static.sh  →  nuxt generate  →  同步到 /var/www/blog/  →  nginx reload
```

**单一节点**：所有服务（SQLite / Redis / Backend / Nginx）跑在同一台 ECS 上，**systemd 编排**（无 docker），**接受单点风险**（个人博客可接受，二阶段可加 SLB）。

## 五、网络与安全

### 5.1 阿里云安全组
- **入站**：
  - 80 (HTTP) — 全开（301 跳转用）
  - 443 (HTTPS) — 全开
  - 22 (SSH) — **仅你的家庭/公司 IP 段**（不是 0.0.0.0/0）
  - 3306 / 6379 — **不开**（MySQL/Redis 跑在 Docker 内网，不暴露公网）
  - 8080 — **不开**（Backend 仅给 Nginx 反代，不暴露公网）
- **出站**：全开（后端可能需要访问阿里云 API / Maven 镜像）

### 5.2 SSH 加固
- **密钥对登录**（不开放密码）
- **非标端口**（如 2222）—— ECS 安全组 + `/etc/ssh/sshd_config` 同步改
- **fail2ban** 防爆破
- **禁用 root 远程登录**（用 deploy 用户 + sudo）
- **首次登录后立即**：`passwd -l root` 锁 root 账号

### 5.3 应用层
- **HTTPS 强制**：Nginx 80 → 301 → 443
- **CORS 收紧**：只允许 `https://yourname.com`（不再用 `*`）
- **Swagger UI**：生产环境关闭（`blog.swagger.enabled=false`）
- **JWT secret**：32+ 位强随机（dev 环境是写死的，必须改）
- **密码加密**：**BCrypt 替换明文比对**（用 `org.springframework.security:crypto`）
- **限流**：登录接口 5 req/min，API 通用 20 req/s（详见 nginx.conf）
- **CVE 防护**：定期 `mvn dependency:tree` 扫漏洞，OpenJDK 跟最新

## 六、CI/CD 流程

### 6.1 完整流程（GitHub Actions + 阿里云 ACR + ECS）

```
开发者本地 git push origin main
        ↓
GitHub Actions 触发（.github/workflows/deploy.yml）
        ↓
┌───────────────────────────────────┐
│ Job 1: build-backend              │
│  - mvn package                    │
│  - docker build (后端 Dockerfile) │
│  - docker push → 阿里云 ACR       │
└───────────────────────────────────┘
        ↓
┌───────────────────────────────────┐
│ Job 2: build-frontend             │
│  - npm ci                         │
│  - npm run build                  │
│  - docker build (前端 Dockerfile) │
│  - docker push → 阿里云 ACR       │
└───────────────────────────────────┘
        ↓
┌───────────────────────────────────┐
│ Job 3: deploy (SSH 到 ECS)        │
│  - ssh deploy@ecs 'bash deploy.sh'│
│  - deploy.sh:                     │
│    1. docker-compose pull         │
│    2. docker-compose up -d        │
│    3. health check                │
│    4. rollback on failure         │
└───────────────────────────────────┘
```

### 6.2 镜像仓库（阿里云 ACR 个人版）
- 免费额度：300 镜像 / 3 命名空间 / 不限流量
- 命名空间：`myblog`
- 镜像仓库：
  - `myblog/backend:latest`
  - `myblog/frontend:latest`
- 凭证：阿里云控制台"访问凭证" → 创建 ACR 登录密码

### 6.3 GitHub Secrets 配置
在 GitHub 仓库 Settings → Secrets 加：
- `ALIYUN_ACR_REGISTRY` — `registry.cn-hongkong.aliyuncs.com`（或新加坡）
- `ALIYUN_ACR_USERNAME`
- `ALIYUN_ACR_PASSWORD`
- `ECS_SSH_KEY` — 私钥（base64 编码）
- `ECS_HOST` — ECS 公网 IP
- `ECS_USER` — `deploy`

### 6.4 回滚策略
- `deploy.sh` 保留最近 3 个镜像版本
- 失败时自动 `docker-compose up -d <previous-tag>`
- 数据库迁移脚本用 Flyway / Liquibase（首期无，未来加）

## 十一、备份与灾备

### 11.1 数据库（v2.6+ SQLite 一文件）
- **脚本**：`scripts/backup.sh`（**待新建**）或手工命令：
  - `sqlite3 /opt/myblog/blog.db ".backup /opt/myblog/backups/blog-$(date +%Y%m%d-%H%M%S).db"`
  - **优势**：在线热备份（不锁库，SQLite WAL 模式）；无 mysqldump 复杂度
  - 保留 7 天本地
  - 同步到阿里云 OSS（冷存，¥0.0033/GB/月）
- **cron**：`0 4 * * * bash /opt/myblog/scripts/backup.sh`（避开 rebuild 时段）
- **恢复测试**：每月 1 号演练一次（恢复 → 验证 → 删）

> **v2.5 之前的 mysqldump 方案**（**v2.6+ 弃用**）：
> - `mysqldump --single-transaction --routines --triggers blog | gzip > /data/backup/blog-$(date +%Y%m%d).sql.gz`
> - 已被 SQLite `.backup` 命令替代（更轻、不依赖 mysqldump）

### 11.2 文件存储
- **/data/uploads/**：本地 + 同步到 OSS 冷存（每日）
- **OSS 开启版本控制**（误删可恢复）

### 11.3 ECS 整机
- **ECS 镜像**：每周一次（用于快速恢复 / 弹性扩容）
- **配置备份**：`docker-compose.prod.yml` / `nginx.conf` / `application-prod.yml` / `scripts/` 入 git 仓库

### 11.4 密钥管理
- 数据库密码 / JWT secret / GitHub Secrets → 阿里云 KMS 加密存储（不写在环境变量明文）
- 个人项目可用 `.env` 文件 + `chmod 600`（部署时手动创建，不入 git）

## 十二、风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 境外 ECS 国内访问慢 | 用户体验 -20-50ms | 首期可接受；二阶段上阿里云 CDN（香港/新加坡源）+ 智能解析 |
| ECS 单点故障 | 全站不可用 | 个人博客可接受；二阶段 SLB + 多 ECS |
| 自装 MySQL 误操作 | 数据丢失 | 每日自动备份 + 每月恢复演练 |
| /data/uploads/ 磁盘满 | 上传失败 | 监控 + 定期归档 + 同步 OSS |
| 后端 jar 漏洞 | 安全风险 | 跟最新 OpenJDK 8uXX / 定期 `dependency:tree` 扫 |
| certbot 续期失败 | HTTPS 过期 | 监控 + 自动续期脚本 + 备证书 |
| GitHub Actions 失败 | 部署卡住 | `on: workflow_dispatch` 手动触发 + 邮件通知 |
| ACR 凭证泄露 | 镜像被推恶意版本 | RAM 子账号 + ACR 仓库级别权限 + 凭证定期轮换 |

## 十三、推荐执行路径

- **第一阶段（最低成本上线）**：境外 ECS 轻量 + 自装 MySQL/Redis + 本地存储 + GitHub Actions/ACR = **~¥60-70/月**
- **第二阶段（稳定 + 监控）**：加自建监控脚本 + 阿里云云监控 + 备份到 OSS 冷存 = **~¥80/月**
- **第三阶段（高可用）**：阿里云 CDN（国内加速）+ SLB + 多 ECS = **~¥200/月**

个人博客建议先到第一/第二阶段，第三阶段等流量起来再说。

### ADR-001：选择境外免备案
- **状态**：已采纳（2026-06-07）
- **背景**：境内备案需 7-20 天，提交身份证 + 人脸核验 + 资料
- **决策**：用阿里云香港轻量 ECS，免备案
- **后果**：
  - ✅ 即开即用
  - ❌ 国内访问 +20-50ms 延迟
  - 🔄 二阶段可上 CDN 智能解析（境外源 → 境内 CDN 边缘）

### ADR-002：选择自装数据库
- **状态**：已采纳（2026-06-07）
- **背景**：阿里云 RDS 1C1G ¥30/月，备份/监控/高可用托管；ECS 自装 ¥0 但需自己备份
- **决策**：ECS 自装 MySQL 8.0（Docker container + volume 持久化）
- **后果**：
  - ✅ 成本 -¥30/月
  - ❌ 无自动备份（用 mysqldump + cron 补）
  - ❌ 无自动高可用（单点故障）
  - 🔄 业务量增长后再迁 RDS（mysqldump → RDS 平滑迁移）

### ADR-003：选择本地文件存储
- **状态**：已采纳（2026-06-07）
- **背景**：阿里云 OSS ¥10/月起，含 CDN 回源；ECS 本地磁盘 + Nginx serve ¥0
- **决策**：ECS 本地磁盘 `/data/uploads/`，Nginx `location /uploads/ { alias ...; }`
- **后果**：
  - ✅ 成本 -¥10/月
  - ❌ ECS 故障 = 文件丢失（用每日同步到 OSS 冷存缓解）
  - 🔄 文件量 > 50G 时迁 OSS

### ADR-004：选择 GitHub Actions + 阿里云 ACR
- **状态**：已采纳（2026-06-07）→ **v2.6+ 简化**（无 docker，无需 ACR 镜像推送）
- **背景**：scp 简单（无 CI）vs GitHub Actions 简单版 vs 阿里云云效完整版
- **决策**：
  - v2.5 之前：GitHub Actions 构建镜像 → 推阿里云 ACR → ECS pull + restart
  - **v2.6+**：scp jar + `scripts/deploy-sqlite.sh` 一键部署（无镜像，ACR 不再使用）
- **后果**：
  - ✅ 标准化（公开仓库免费、ACR 个人版免费）—— **v2.6+ 不再需要**
  - ✅ 镜像版本可追溯 —— **v2.6+ 改为 git tag 追溯**
  - ✅ 一键回滚（指定 tag）—— **v2.6+ 改为 git checkout 上一 tag + 重跑 deploy**
  - 🔄 失败有邮件 + webhook 通知

### ADR-005（2026-06-17）：v2.6.0 改用 SQLite + 砍 docker
- **状态**：已采纳
- **背景**：
  - 1C2G 跑 5 容器 Docker Compose 内存吃紧（MySQL ~150MB + Nuxt SSR node 150-250MB + 其他 ~200MB，挤占 JVM heap 到 256MB）
  - 个人博客数据量 < 100MB，MySQL 8.0 显得过重
  - 1C2G 跑 1C2G ECS（~¥30/月）比 2C2G（~¥60/月）便宜一半
- **决策**：
  - 数据库：MySQL 8.0 → **SQLite 3.45**（一文件 0 内存，Hikari 单连接）
  - 缓存：redis:7-alpine 容器 → **apt 装 redis-server** 系统服务
  - 编排：docker-compose 5 容器 → **systemd**（myblog.service 单服务）
  - MySQL 降级为可选 profile（`spring.profiles.active=*,mysql`）
- **后果**：
  - ✅ 月成本 ¥60 → ¥30
  - ✅ 砍 docker 编排复杂度（`deploy-sqlite.sh` 一键完成）
  - ✅ JVM heap 256MB → 384MB（释放的内存给后端）
  - ❌ SQLite 单写者锁（5 并发排队 ~5 秒，个人博客可接受）
  - ❌ 业务 SQL 必须跨方言兼容（已统一 38 处）
  - 🔄 数据量 > 1GB 时迁回 MySQL（profile 切换，零代码改动）

### ADR-006（2026-06-17）：v2.7.0 改前端全静态
- **状态**：已采纳
- **背景**：
  - v2.5 之前前端跑 `nuxt build` SSR 模式，node 20-alpine 容器吃 150-250MB
  - 个人博客公开页（首页/文章/归档/标签/关于）内容相对静态，无需 SSR
  - SEO 收录：CSR 空 HTML 不利于百度/Google 收录
- **决策**：
  - 构建：`nuxt build` → **`nuxt generate`**（产出 `.output/public/` 静态文件）
  - 运行时：node + Nitro server → **nginx:alpine** 静态服务（10-20MB 内存）
  - 公开页 build 时预渲染成 HTML（13 个静态 HTML）
  - admin 路由不预渲染（`ignore: '/admin/**'` + SPA fallback）
  - 新文章发布走**每日凌晨 3 点 cron rebuild**（延迟 0-24h）
- **后果**：
  - ✅ 前端内存 150-250MB → 10-20MB
  - ✅ Docker 镜像 ~200MB → ~50MB
  - ✅ 公开页 SEO 可收录
  - ❌ 新文章 0-24h 延迟可见（cron 凌晨 3 点 rebuild）
  - 🔄 写文章频率提升后改事件触发 rebuild（v2.7.0 backlog）
