# 系统升级方案设计

> 版本：v1.2
> 更新日期：2026-07-09
> 状态：现行方案
> 关联任务：20260708-DEV-001 ~ 20260708-DEV-004

---

## 1. 需求背景

博客系统部署在 ECS 服务器上，此前版本升级需要 SSH 登录服务器手动执行脚本，存在以下问题：

1. **操作门槛高**：需要熟悉 Linux 命令行和部署流程
2. **版本管理缺失**：需手动查看 GitHub Release 确认可用版本
3. **升级过程不透明**：日志仅在 SSH 终端输出，无法远程查看
4. **无升级记录**：无法追溯历史升级操作

本方案实现管理后台一键升级，覆盖「版本选择 → 执行部署 → 日志跟踪 → 历史记录」全流程。

---

## 2. 设计目标

| 维度 | 手动部署（旧） | 系统升级（新） |
|------|--------------|--------------|
| 操作方式 | SSH 登录 → 手动执行脚本 | 管理后台选版本 → 一键升级 |
| 版本管理 | 无，需手动查 GitHub Release | 下拉框列出所有 Release 版本 |
| 升级日志 | SSH 终端实时输出 | SSE 流式推送到浏览器 |
| 升级记录 | 无 | `upgrade_record` 表持久化 |
| 并发保护 | 无 | 文件锁 + 409 拒绝重复升级 |
| 安全确认 | 无 | 数据覆盖需输入"确认" |
| 审计追踪 | 无 | `audit_log` 表记录升级/回滚操作 |

### 3.2 数据流

```
用户点击「开始升级」
    │
    ▼
前端 fetch POST /admin/upgrade（SSE 流）
    │
    ▼
UpgradeController.upgrade()
    │ 1. 参数校验
    │ 2. 创建 upgrade_record（PENDING）
    │ 3. 标记 RUNNING
    │ 4. 返回 SseEmitter
    │
    ▼ （后台线程）
HttpURLConnection → upgrade-agent:28081/upgrade
    │
    ▼
upgrade-agent._run_deploy()
    │ 1. subprocess.Popen(deploy-server.sh)
    │ 2. 逐行读取 stdout
    │ 3. SSE 推送 event:log
    │ 4. 进程结束 → SSE 推送 event:done
    │
    ▼ （UpgradeController 后台线程读取 agent SSE）
逐行转发 event:log → 前端
收到 event:done → 更新 upgrade_record（SUCCESS/FAILED）
                → 记录 audit_log（UPGRADE）
    │
    ▼
前端显示升级完成，刷新状态
```

## 4. 模块详细设计

### 4.1 upgrade-agent（Python 代理）

**文件**：`scripts/upgrade-agent.py`

**技术选型**：Python 3 标准库（http.server + threading），零外部依赖

**依赖**：仅 Python 标准库，无需安装 aiohttp

**核心逻辑**：

```python
# 升级锁
class UpgradeLock:
    def acquire(self) -> bool:
        self._fd = open(self.path, "w")
        fcntl.flock(self._fd, fcntl.LOCK_EX | fcntl.LOCK_NB)  # 非阻塞
        return True  # 获取成功

    def release(self):
        fcntl.flock(self._fd, fcntl.LOCK_UN)
        os.unlink(self.path)

# SSE 推送
def _send_sse(response, event, data):
    response.write(f"event: {event}\ndata: {data}\n\n".encode())

# 升级执行
def _run_deploy(version, mode, import_db, response):
    process = subprocess.Popen(
        ["bash", DEPLOY_SCRIPT, version],
        stdout=subprocess.PIPE, stderr=subprocess.STDOUT,
        env=env, bufsize=1
    )
    for line in iter(process.stdout.readline, ""):
        _send_sse(response, "log", line)  # 逐行推送
    _send_sse(response, "done", json.dumps({"success": success}))
```

**端点规格**：

| 方法 | 路径 | 请求体 | 响应 | 说明 |
|------|------|--------|------|------|
| POST | `/upgrade` | `{version, mode, importDb, confirm}` | SSE stream | 触发升级 |
| GET | `/status` | — | `{status, version, mode, ...}` | 查询状态 |
| GET | `/logs?limit=200` | — | `{logs: [...], total: N}` | 查询日志 |
| GET | `/health` | — | `{status: "UP"}` | 健康检查 |

**错误码**：

| HTTP 码 | 含义 |
|---------|------|
| 200 | 成功（SSE 流或 JSON） |
| 400 | 参数错误（version 为空 / mode 非法 / confirm 缺失） |
| 409 | 升级进行中（文件锁未释放） |

### 4.2 UpgradeService（后端服务）

### 4.3 UpgradeController（后端控制器）

**文件**：`backend/blog-app/src/main/java/com/blog/upgrade/UpgradeController.java`

**端点规格**：

| 方法 | 路径 | 认证 | 说明 |
|------|------|------|------|
| POST | `/admin/upgrade` | admin | 触发升级（SSE 流式响应，600s 超时） |
| GET | `/admin/upgrade/status` | admin | 查询状态（当前版本 + agent 状态 + 升级状态） |
| GET | `/admin/upgrade/versions` | admin | GitHub Release 列表 |
| GET | `/admin/upgrade/records?page=1&size=20` | admin | 升级历史（分页） |
| POST | `/admin/upgrade/rollback` | admin | 回滚记录（仅审计，不执行） |

**升级流程**：

```
1. 参数校验
   - version 不能为空
   - mode 必须是 "full" 或 "init"
   - importDb=true 时 confirm 必须是 "确认"

2. 创建升级记录
   UpgradeRecord record = upgradeRecordService.createRecord(
       version, mode, importDb, operatorId, operatorName, ip, fromVersion)
   upgradeRecordService.markRunning(record.getId())

3. 启动 SSE 流
   SseEmitter emitter = new SseEmitter(600_000L)  // 10 分钟超时

4. 后台线程调用 upgrade-agent
   HttpURLConnection conn = new URL("http://127.0.0.1:28081/upgrade")
   conn.getOutputStream().write(requestBody)

5. 逐行读取 SSE 事件流
   while ((line = reader.readLine()) != null) {
       if (line.startsWith("event: done")) {
           // 升级完成
           upgradeRecordService.markSuccess(record.getId())
           auditLogService.record(operator, "UPGRADE", "系统升级", detail, ip)
       } else if (line.startsWith("data: ")) {
           emitter.send(SseEmitter.event().name("log").data(data))
       }
   }

6. 异常处理
   catch (Exception e) {
       upgradeRecordService.markFailed(record.getId(), e.getMessage())
       auditLogService.record(operator, "UPGRADE", "系统升级", detail + ", result=failed", ip)
   }
```

### 4.4 UpgradeRecordService（升级记录）

**文件**：`backend/blog-app/src/main/java/com/blog/upgrade/UpgradeRecordService.java`

**状态机**：
```
PENDING ──→ RUNNING ──→ SUCCESS
                    └──→ FAILED
```

**方法**：

| 方法 | 说明 |
|------|------|
| `createRecord(...)` | 创建记录，状态 PENDING |
| `markRunning(id)` | 更新状态为 RUNNING |
| `markSuccess(id)` | 更新状态为 SUCCESS，设置 finishedAt |
| `markFailed(id, msg)` | 更新状态为 FAILED，设置 finishedAt + errorMessage |
| `list(page, size)` | 分页查询，按 id DESC 排序 |

**SQL 实现**（JdbcTemplate，跨 SQLite/MySQL 一致）：

```sql
-- 创建
INSERT INTO upgrade_record (target_version, mode, import_db, status, started_at, from_version, operator_id, operator_name, ip)
VALUES (?, ?, ?, 'PENDING', ?, ?, ?, ?, ?)

-- 更新状态
UPDATE upgrade_record SET status = ? WHERE id = ?

-- 分页查询
SELECT id, target_version, mode, import_db, status, started_at, finished_at, from_version, error_message, operator_name, ip
FROM upgrade_record ORDER BY id DESC LIMIT ? OFFSET ?
```

## 5. 数据模型

### 5.1 upgrade_record 表

```sql
-- SQLite
CREATE TABLE IF NOT EXISTS upgrade_record (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  target_version  VARCHAR(32)  NOT NULL,     -- 目标版本号，如 v5.3.0
  mode            VARCHAR(16)  NOT NULL,     -- full（全量代码升级）/ init（初始化）
  import_db       TINYINT      NOT NULL DEFAULT 0,  -- 是否导入数据
  status          VARCHAR(16)  NOT NULL,     -- PENDING / RUNNING / SUCCESS / FAILED
  started_at      DATETIME     NOT NULL,     -- 升级开始时间
  finished_at     DATETIME,                  -- 升级完成时间
  from_version    VARCHAR(32),               -- 升级前版本号
  error_message   TEXT,                      -- 失败信息
  operator_id     BIGINT,                    -- 触发人 uid
  operator_name   VARCHAR(64),               -- 触发人 username
  ip              VARCHAR(45)                -- 操作 IP
);
CREATE INDEX IF NOT EXISTS idx_upgrade_record_started_at ON upgrade_record(started_at DESC);
CREATE INDEX IF NOT EXISTS idx_upgrade_record_status ON upgrade_record(status);
```

```sql
-- MySQL
CREATE TABLE IF NOT EXISTS `upgrade_record` (
  `id`              BIGINT        NOT NULL AUTO_INCREMENT,
  `target_version`  VARCHAR(32)   NOT NULL                COMMENT '目标版本号',
  `mode`            VARCHAR(16)   NOT NULL                COMMENT 'full/init',
  `import_db`       TINYINT       NOT NULL DEFAULT 0      COMMENT '是否导入数据',
  `status`          VARCHAR(16)   NOT NULL                COMMENT 'PENDING/RUNNING/SUCCESS/FAILED',
  `started_at`      DATETIME      NOT NULL                COMMENT '升级开始时间',
  `finished_at`     DATETIME      DEFAULT NULL            COMMENT '升级完成时间',
  `from_version`    VARCHAR(32)   DEFAULT NULL            COMMENT '升级前版本号',
  `error_message`   TEXT          DEFAULT NULL            COMMENT '失败信息',
  `operator_id`     BIGINT        DEFAULT NULL            COMMENT '触发人 uid',
  `operator_name`   VARCHAR(64)   DEFAULT NULL            COMMENT '触发人 username',
  `ip`              VARCHAR(45)   DEFAULT NULL            COMMENT '操作 IP',
  PRIMARY KEY (`id`),
  INDEX `idx_upgrade_record_started_at` (`started_at` DESC),
  INDEX `idx_upgrade_record_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

## 6. 安全设计

| 风险 | 防护措施 |
|------|---------|
| 未授权访问 | AdminAuthFilter 拦截 `/admin/*`，需 JWT token + 设备授权 |
| 并发升级 | fcntl 文件锁（`LOCK_EX \| LOCK_NB`），获取失败返回 409 |
| 误操作数据覆盖 | `importDb=true` 时必须输入"确认"二字 |
| agent 被外部调用 | 监听 `127.0.0.1`，仅本地访问 |
| GitHub token 泄露 | 环境变量传递，不写入日志或响应体 |
| 升级脚本执行权限 | agent 以 root 运行，deploy-server.sh 内部有权限校验 |

## 10. 生产部署配置

### 10.1 环境变量（myblog.env）

```bash
# 系统升级模块配置
GITHUB_TOKEN=你的GitHub PAT（需主仓库 repo 权限）
GITHUB_REPO=YuanYii/my-blog-prov
```

### 10.2 部署方式

deploy-server.sh 自动处理 upgrade-agent 安装：

- **systemd 模式**（生产 ECS）：自动安装 upgrade-agent.service
- **supervisord 模式**（Docker/LOCAL_SIM）：自动配置 upgrade-agent.conf

### 10.3 手动安装（备用）

```bash
# 复制脚本
sudo cp /opt/myblog/scripts/upgrade-agent.py /opt/myblog/scripts/
sudo cp /opt/myblog/scripts/upgrade-agent.service /etc/systemd/system/

# 启动服务
sudo systemctl daemon-reload
sudo systemctl enable upgrade-agent
sudo systemctl start upgrade-agent

# 验证
curl -s http://127.0.0.1:28081/health
```

### 10.4 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| Connection refused | agent 未运行 | `sudo systemctl start upgrade-agent` |
| 版本列表为空 | GITHUB_TOKEN 未配置 | 在 myblog.env 中添加 |
| upgrade_record 表不存在 | deploy-server.sh 增量迁移未执行 | 手动建表或重新部署 |

## 11. 已知限制与后续规划

### 11.1 已知限制

1. **upgrade-agent 使用标准库**：无需安装额外依赖（原版依赖 aiohttp，已改为 http.server + threading）
2. **GitHub API 速率限制**：未认证 60 次/小时，认证 5000 次/小时
3. **私有仓库需 token**：`GITHUB_TOKEN` 必须有 `repo` 权限，配置在 `myblog.env`
4. **升级期间服务中断**：deploy-server.sh 重启 Spring Boot，预计 1-3 分钟
5. **回滚仅记录**：rollback 端点只记录审计日志，实际执行需通过升级代理部署旧版本
6. **SSE 连接超时**：deploy-server.sh 重启后端时 SSE 连接可能断开，upgrade_record 卡在 RUNNING

### 11.2 后续规划

1. **升级通知**：升级完成后推送通知（邮件/飞书）
2. **版本对比**：展示当前版本与目标版本的 changelog 差异
3. **自动回滚**：升级失败后自动回滚到上一版本
4. **升级锁 UI**：agent 状态为 running 时禁用升级按钮
5. **reconcile 机制**：启动时检测 RUNNING 状态的 upgrade_record 并更新
