## 2. 鉴权契约（AdminAuthFilter）

放行判定**不再硬编码**，统一查 `api_whitelist` 表做**最长前缀优先**匹配（`ApiWhitelistService.matchPath`）：

1. `OPTIONS` 预检 → 直接放行（CORS）。
2. 命中 `type=admin` 前缀 → 必须鉴权。
3. 未命中任何前缀 → 防御性默认放行（新增接口不误伤）。
4. 命中 `type=public`：
   - GET / HEAD → 匿名放行；
   - 写方法（POST/PUT/DELETE/PATCH）→ 默认要求鉴权，仅 `POST /auth/login`、`POST /comments`（裸路径）经 `isPublicWriteAllowed` 放行。

鉴权通过后还要校验：

- token 的 `uid` claim 存在且 token 未过期（否则 401 / 1007）；
- `X-Device-Id` 对应设备在 `admin_device` 中为 `approved`（待授权 2001 / 已吊销 2002）；
- token 的 `deviceId` claim 必须等于请求头 `X-Device-Id`（防 token 借用）。

> **历史漏洞（已修复）**：2026-06-12 前，filter 只按 path 前缀放行、不看 HTTP 方法，导致 `/articles`、`/comments` 下的写端点（发文/删文/清空评论审核队列等）匿名可调用。现已通过「public 前缀下写方法默认鉴权」+「api_whitelist 增加 admin 子前缀」双层修复。

`api_whitelist` 种子（节选）：

| path_prefix | type |
|-------------|------|
| `/api/v1/health` | public |
| `/api/v1/articles` | public |
| `/api/v1/comments` | public |
| `/api/v1/auth` | public |
| `/api/v1/public/settings` | public |
| `/api/v1/rss` | public |
| `/api/v1/rss.xml` | public |
| `/api/v1/sitemap.xml` | public |
| `/api/v1/seo` | public |
| `/api/v1/admin/*`（dashboard/articles/comments/categories/tags/devices/settings…） | admin |

## 3. 字段一致性

统一约定：响应字段一律 **camelCase**，DB 列 `snake_case` 经 SQL `AS` 别名映射；统一响应体 `{ code, data, message }`。

MVP v1 审计发现的 6 处字段/结构/鉴权不一致（Comment 字段、Settings social/preferences 结构、`/admin/dashboard` 漏鉴权等）**均已在 v1 修复并沿用至今**，详见附录。本轮新增端点（设备、API 白名单、public profile/settings、archives、techstack/experience、附件、升级、审计日志、SEO 等）字段命名与上述约定一致，前后端调用对齐。

> **上传端点重复（2026-06-13 发现并修复）**：存在两个上传端点——`/admin/settings/upload`（`SettingsController`，含扩展名白名单 + magic bytes 校验）与 `/admin/uploads`（`UploadController`，前端实际调用）。此前 `/admin/uploads` 只校验客户端可伪造的 `Content-Type` 请求头，缺 magic bytes，已登录 admin 可上传 `.html/.svg` 伪装图片经 `/uploads/**` 回源构成存储型 XSS。已为 `/admin/uploads` 补齐与 `/admin/settings/upload` 同等的「扩展名白名单 + magic bytes」校验。旧端点 `/admin/settings/upload` 前端未再使用，保留备查（建议后续删除以消除重复）。

| 500 | 服务器内部错误 | 1006 | 用户名或密码错误 |
| 2001 | 设备未授权 | 1007 | Token 无效或已过期 |
| 2002 | 设备已吊销 | 2003 | 不能吊销当前登录设备 |
| 3002 | 备份记录正在运行中（v4.2.1） | — | — |

`GlobalExceptionHandler` 另统一处理：参数校验（400）、上传超限、缺参、类型不匹配、404 NoHandler、405 方法不支持等。
