# 博客文章风格规范（升级版）

> 基于历史文章分析 + 读者体验优化建议整合而成
> 最后更新：2026-06-24

---

## 一、核心定位（不变）

**一句话定义**：一个踩过坑的人，把解决方案一步步截图讲给你听，顺便提醒你哪里容易出错。

**目标读者**：遇到相同问题的开发者（初级~中级）
**核心价值**：读者能照着步骤做出来，并且在偏差情况下知道如何应对

---

## 二、文章结构规范

### 标准结构模板

```
标题（问题现象 + 环境/版本，不加"实测有效"类标签）

【适用场景】← 新增
一句话说明本文适用于什么环境、什么版本、什么现象
（例：适用于 PyCharm 2020+ / JDK 1.8 / CentOS 7）

问题现象描述
- 文字描述 + 配截图
- 说明"不影响运行"还是"会导致失败"，帮助读者判断紧急程度

原因分析
- 一句话即可，不必深入原理
- 格式：这种情况一般是 XXX 导致的

解决方案（编号步骤）
步骤 N：操作标题
- 文字说明（做什么、为什么这样做，一句话原理）
- 配截图
- 关键路径/命令用代码块标注

【常见问题】← 新增
- Q1: 如果 XXX 不一样怎么办？
- Q2: 操作后出现 XXX 怎么处理？
（列出 2-3 个可能的偏差情况）

总结
- 一句话重申核心解法
- 可选：谦逊留白（"如有其他情况欢迎补充"）
```

## 三、标题规范

### 命名规则

| 类型 | 格式 | 示例 |
|------|------|------|
| 单篇 | 问题现象 + 解决方案关键词 +（适用版本） | `PyCharm 代码报红但项目正常运行——Python 解释器配置（2020+）` |
| 系列 | 主标题_(N)副标题（统一格式） | `JavaWeb 部署_阿里云 Windows Server 2012_(1)本地上传文件到服务器` |
| 报错类 | 报错关键词 + 触发场景 | `SpringBoot 集成 Swagger 控制台报错 Exception Processing ErrorPage` |

### 避免的标题写法

- ❌ `——实测有效！`（改为在文中说明验证环境）
- ❌ 过于宽泛：`Java 学习笔记`、`Linux 使用技巧`

---

## 四、语言风格规范

### 恒定句式（保留）

| 句式 | 用途 | 示例 |
|------|------|------|
| `如图所示，` | 引导截图 | 如图所示，在弹出框中选择图或表 |
| `这种情况一般是...` | 原因推断 | 这种情况一般是选择错误的 Python 解释器导致的 |
| `切记：...` | 风险提示 | 切记：项目运行时 tomcat 的窗口不能关闭！ |
| `...即可` | 结果确认 | 点击确定即可完成配置 |

### 新增规范

**步骤说明的"为什么"补充**：关键步骤在操作后加一句话原理（用括号或换行，不超过一行）

```
1. 配置 JAVA_HOME 环境变量
   新建系统变量，变量名为 JAVA_HOME，值为 jdk 的安装目录
   （让系统在任何目录下都能找到 java 命令）
```

**适用环境标注**：在文章开头或标题括号内注明，不用"实测有效"这类主观标签

```
验证环境：JDK 1.8.0_51 / Tomcat 8.0 / Windows Server 2012
```

## 五、代码块规范（统一）

### 格式要求

- 统一使用三个反引号包裹
- 注明语言类型
- 关键命令单独成块，不嵌在正文里

```bash
# 正确示例
java -version
```

```java
// 正确示例
String[] resultArr = result.trim().split("");
```

### 避免

- ❌ 不用缩进四个空格代替代码块（CSDN 渲染不一致）
- ❌ 代码块内混用中英文标点

---

## 六、截图规范

| 要求 | 说明 |
|------|------|
| 必须有文字引导 | 每张截图前都有`如图所示，`引导 |
| 标注关键位置 | 截图中用红框/箭头标注点击位置（如果可以的话） |
| 完整路径可见 | 文件路径类截图保证路径完整显示 |
| 命令行结果完整 | 命令 + 输出一起截图，不截断 |

---

## 七、系列文章规范（新增）

### 每篇开头

```
【前置要求】← 新增
建议先阅读：[文章 N 标题](链接)
```

### 每篇结尾

```
【系列导航】
上一篇：[文章 N-1 标题](链接)（如有）
下一篇：[文章 N+1 标题](链接)（如有）
```

---

## 八、常见问题写法（新增）

放在文章结尾、总结之前。格式如下：

```
【常见问题】

> Q：我的界面和截图不一样怎么办？
> A：不同版本的 XXX 界面可能有差异，但核心步骤相同，找到对应功能的入口即可。

> Q：操作后出现 XXX 错误？
> A：一般是 XXX 导致的，检查 XXX 是否配置正确。
```

不用每条都长篇回答，点到为止。

---

## 九、模仿检查清单

写完文章后逐项检查：

- [ ] 标题是否包含了问题现象和关键解决方案词？
- [ ] 开头是否有「适用场景/验证环境」说明？
- [ ] 问题现象是否有截图？
- [ ] 每个关键步骤是否有「为什么这样做」的一句话说明？
- [ ] 代码块是否统一格式（三个反引号 + 语言类型）？
- [ ] 是否有「切记/注意」类风险提示？
- [ ] 结尾是否有「常见问题」？
- [ ] 系列文章是否有「前置要求」和「系列导航」？
- [ ] 全文是否有冗余感叹号或过度自信的表述？
