## 维度 1：API 契约一致性

**要回答的问题**：文档里列的端点数量、路径、鉴权、前端调用方跟代码是否一致？

### 检查步骤

```
步骤 A — 收集代码侧端点
  扫描所有 *Controller.java：
    find backend -name "*Controller.java" | xargs grep -E \
      '@(GetMapping|PostMapping|PutMapping|DeleteMapping|RequestMapping)'
  提取每个端点的：HTTP 方法、完整路径、所在 Controller

步骤 B — 收集文档侧端点
  从 接口契约审计报告.md §1 提取全量端点表
  从 设计方案.md §6.1 提取 API 表

步骤 C — 逐项对照
  □ 端点总数是否匹配
  □ 每个端点的 HTTP 方法是否正确
  □ 每个端点的路径是否正确
  □ 鉴权标注（公开/鉴权）是否与实际 Filter 配置一致
  □ 前端调用方列的文件名是否存在（检查 frontend/ 对应路径）
  □ 文档中标注的"用途"是否与代码逻辑一致
```

### 审计报告标注规范

表格格式：`# | 方法 | 路径 | 鉴权 | 前端调用 | 用途`
- 鉴权列用 `公开` / `鉴权`
- 前端调用列写实际文件路径（如 `admin/login.vue`）

```

  □ 每张表的字段名是否与 Java 实体字段一致（驼峰 ↔ 下划线）
  □ 字段类型是否兼容（如 Java String ↔ SQL VARCHAR）

### 脚本 2：脚本与操作手册一致性检查

```bash
#!/bin/bash
# 检查操作手册中的命令是否在 scripts/ 中存在对应脚本

check_manual_commands() {
  local manual="$1"
  echo "检查文档：$manual"
  echo "---"

  # 提取文档中的所有 .sh 脚本引用
  grep -oP '`[a-z]+-[a-z]+\.sh`' "$manual" | tr -d '`' | while read -r script; do
    if [ ! -f "scripts/$script" ]; then
      echo "❌ 文档引用了不存在的脚本：scripts/$script"
    else
      echo "✅ 脚本存在：$script"
    fi
  done
}

# 使用示例
check_manual_commands "docs/项目部署操作手册.md"
check_manual_commands "docs/数据备份操作手册.md"
```

### 脚本 3：环境配置示例一致性检查

```bash
#!/bin/bash
# 检查 .example 文件中的配置项是否与文档一致

check_example_consistency() {
  local example_file="$1"
  local manual_file="$2"

  echo "检查配置示例：$example_file"
  echo "对照文档：$manual_file"
  echo "---"

  # 提取 .example 中的所有配置项（非注释行）
  grep -E '^[A-Z_]+=' "$example_file" | cut -d'=' -f1 | while read -r config_key; do
    # 在文档中查找该配置项
    if grep -q "$config_key" "$manual_file"; then
      echo "✅ 配置项存在：$config_key"
    else
      echo "⚠️ 配置项在文档中未找到：$config_key"
    fi
  done
}

# 使用示例
check_example_consistency "scripts/deploy-server.env.example" "docs/项目部署操作手册.md"
```

### 脚本 4：变更日志与版本号一致性检查

```bash
#!/bin/bash
# 检查 changelog 版本号与 git tag、pom.xml 的一致性

check_changelog_consistency() {
  echo "检查变更日志一致性"
  echo "---"

  # 1. 提取 changelog 中的所有版本号
  echo "1. Changelog 版本号："
  grep -E '^#+ v[0-9]+\.[0-9]+\.[0-9]+' docs/changelogs/*.md | sed 's/.*v/v/' | sort -V

  # 2. 提取 git tag 中的所有版本号
  echo ""
  echo "2. Git tag 版本号："
  git tag | grep -E '^v[0-9]+\.[0-9]+\.[0-9]+$' | sort -V

  # 3. 提取 pom.xml 中的版本号
  echo ""
  echo "3. pom.xml 当前版本号："
  grep -A 1 '<revision>' backend/pom.xml | grep -oP '[0-9]+\.[0-9]+\.[0-9]+'

  # 4. 对比差异
  echo ""
  echo "4. 差异分析："
  CHANGELOG_VERSIONS=$(grep -E '^#+ v[0-9]+\.[0-9]+\.[0-9]+' docs/changelogs/*.md | sed 's/.*v/v/' | sort -V)
  GIT_TAG_VERSIONS=$(git tag | grep -E '^v[0-9]+\.[0-9]+\.[0-9]+$' | sort -V)

  # 找出在 changelog 中但不在 git tag 中的版本
  comm -23 <(echo "$CHANGELOG_VERSIONS") <(echo "$GIT_TAG_VERSIONS") | while read -r ver; do
    echo "⚠️ Changelog 中有但 git tag 中没有：$ver"
  done

  # 找出在 git tag 中但不在 changelog 中的版本
  comm -13 <(echo "$CHANGELOG_VERSIONS") <(echo "$GIT_TAG_VERSIONS") | while read -r ver; do
    echo "⚠️ Git tag 中有但 changelog 中没有：$ver"
  done
}

# 执行检查
check_changelog_consistency
```

## 使用建议

1. **定期执行**：建议每月执行一次"全量一致性检查"脚本
2. **提交前检查**：每次提交脚本变更前，执行"维度 8"检查
3. **版本发布前**：执行"维度 1 + 2 + 10"检查
4. **配置变更前**：执行"维度 9"检查

## 检查优先级

根据变动频率和风险评估，建议按以下优先级执行检查：

| 优先级 | 维度 | 理由 |
|--------|--------|------|
| **P0** | 维度 8（脚本与操作手册） | 高风险，脚本经常变动 |
| **P0** | 维度 1（API 契约） | 高风险，端点变更频繁 |
| **P1** | 维度 2（数据库 Schema） | 中风险，表结构变更影响大 |
| **P1** | 维度 9（环境配置示例） | 中风险，配置项容易遗漏 |
| **P2** | 维度 10（变更日志） | 中风险，影响版本管理 |
| **P2** | 维度 3（技术栈版本） | 低风险，版本更新频率低 |
| **P3** | 维度 4-7（其他维度） | 低风险，按需检查 |
