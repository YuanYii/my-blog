# my-blog 项目部署操作手册

> **定位**：升级时一步步怎么操作（"how"）。设计决策见 [`项目部署解决方案.md`](项目部署解决方案.md)。
> **适用**：my-blog **v5.0.0+**

---

## 1. 速查

### 1.1 脚本

| 脚本 | 位置 | 用途 |
|---|---|---|
| [`publish-release.sh`](../scripts/publish-release.sh) | 本地 | 构建 jar + 前端 → GitHub Release |
| [`deploy-server.sh`](../scripts/deploy-server.sh) | 服务器 | 从 release 拉资源 → 部署 → 重启 |
| [`sqlite-export.sh`](../scripts/sqlite-export.sh) | dev 本地 | SQLite 加密导出 |
| [`sqlite-import.sh`](../scripts/sqlite-import.sh) | 服务器 | 解密导入 |
| [`blog-backup.sh`](../scripts/blog-backup.sh) | 服务器 | 加密备份 → GitHub Release |

### 1.2 DEPLOY_MODE

| 模式 | 用途 |
|---|---|
| `init` | 首次初始化（建库 + 种子数据）|
| `full`（默认）| 全量升级（保留 DB + 增量 SQL）|
| `full` + `IMPORT_DB=1` | 代码 + 数据一起升级 |
| `docker-create` | 本地 Docker 首次构建 |
| `docker-init` | 本地 Docker 业务初始化 |

### 1.3 各场景数据库行为

> **16 张表**：user / api_whitelist / category / tag / article / article_tag / comment / site_settings / page_view / article_view_log / admin_device / backup_record / restore_record / import_record / ip_ban / _migration_history
> **种子数据**：user 1 条（admin）+ api_whitelist 13 条

| 场景 | DB 行为 | user | api_whitelist | 其他 14 张表 | _migration_history |
|---|---|---|---|---|---|
| §2 init | 删旧 DB → schema 重建 | 🔴→种子 1 条 | 🔴→种子 13 条 | 🔴 全部清空 | 🔴 清空 |
| §3 full | 保留 DB + 增量 SQL | ✅ 保留 | ✅ 保留 | ✅ 保留 | ➕ 追加 |
| §3 full + IMPORT_DB=1 | 全量覆盖 | 🔴 覆盖 | 🔴 覆盖 | 🔴 覆盖 | 🔴 覆盖 |
| §4 手动 SQL | 只执行指定 SQL | ✅ 不动 | ✅ 不动 | ✅ 不动 | 手动 INSERT |
| §5 docker-create | 不动 DB | — | — | — | — |
| §6 docker-init | 等价 full | ✅ 保留 | ✅ 保留 | ✅ 保留 | ➕ 追加 |

## 2. 场景一：项目初始化

首次从零部署。**风险**：所有业务数据清空。

### 2.1 前提

- [ ] JDK 8+、Node.js 20+、Maven
- [ ] `backend/pom.xml` 的 `<revision>` 正确
- [ ] ECS SSH 可达，域名已解析

### 2.2 本地打包

```bash
export GITHUB_REPO=YuanYii/my-blog-prov
./scripts/publish-release.sh
# 完成后从输出获取 TAG
```

### 2.3 服务器部署

```bash
ssh myblog@<ecs-ip>
TAG=<实际tag>
GITHUB_REPO=YuanYii/my-blog-prov
curl -L "https://github.com/$GITHUB_REPO/releases/download/$TAG/deploy-server.sh" \
    -o "deploy-server-$TAG.sh" && chmod +x "deploy-server-$TAG.sh"
export GITHUB_REPO=$GITHUB_REPO
sudo DEPLOY_MODE=init -E "./deploy-server-$TAG.sh" "$TAG"
```

### 2.4 验收

```bash
curl -s http://127.0.0.1/api/v1/health          # 服务正常
curl -sI http://127.0.0.1/                       # 前端 200
curl -s http://127.0.0.1/api/v1/articles | jq '.data.total'  # 期望 0
```

### 2.5 初始化后必做

- [ ] 改 admin 密码
- [ ] 配 `/etc/myblog/myblog.env` 的 `CORS_ORIGINS`（必填）
- [ ] 配设备授权

### 2.6 关键环境变量

| 变量 | 说明 |
|---|---|
| `JWT_SECRET` | 首次自动生成，**绝对不要覆盖** |
| `CORS_ORIGINS` | **必填**，逗号分隔 |
| `BACKUP_ENCRYPTION_PASSWORD` | 首次自动生成，丢失则备份无法解密 |
| `GITHUB_BACKUP_REPO` / `BACKUP_GITHUB_TOKEN` | 启用 GitHub 备份时必填 |

## 3. 场景二：全量代码升级

最常用。DB 保留，跑增量 SQL。

### 3.1 本地打包

```bash
export GITHUB_REPO=YuanYii/my-blog-prov
./scripts/publish-release.sh
```

### 3.2 服务器部署

```bash
ssh myblog@<ecs-ip>
TAG=<实际tag>
GITHUB_REPO=YuanYii/my-blog-prov
curl -L "https://github.com/$GITHUB_REPO/releases/download/$TAG/deploy-server.sh" \
    -o "deploy-server-$TAG.sh" && chmod +x "deploy-server-$TAG.sh"
export GITHUB_REPO=$GITHUB_REPO
sudo -E "./deploy-server-$TAG.sh" "$TAG"
```

### 3.3 验收

```bash
curl -s http://127.0.0.1/api/v1/health
curl -s http://127.0.0.1/api/v1/articles | jq '.data.total'  # 期望 > 0
sqlite3 /opt/myblog/db/blog.db "SELECT * FROM _migration_history ORDER BY executed_at DESC LIMIT 5;"
```

### 3.4 带数据迁移（IMPORT_DB=1）

**风险**：全量覆盖 prod DB，`admin_device` / `page_view` 会清空。

```bash
# 方式 A：手动
bash scripts/sqlite-export.sh --exclude page_view -o /tmp/migration.sql.gz.enc
scp /tmp/migration.sql.gz.enc myblog@<ecs-ip>:/tmp/
ssh -t myblog@<ecs-ip> "sudo bash /opt/myblog/scripts/sqlite-import.sh /opt/myblog/db/blog.db /tmp/migration.sql.gz.enc"

# 方式 B：发布时打包
EXPORT_DB=1 ./scripts/publish-release.sh
IMPORT_DB=1 sudo -E "./deploy-server-<实际tag>.sh" "<实际tag>"
```

## 4. 场景三：增量 SQL 脚本升级（应急）

只补表结构/数据，不动代码。

### 4.1 规范

- 目录：`docs/sql/migrations/`
- 命名：`{YYYYMMDD}_{description}.sql`
- 幂等：`CREATE TABLE IF NOT EXISTS` / `ALTER TABLE ... ADD COLUMN`

### 4.2 执行

```bash
ssh myblog@<ecs-ip>
sqlite3 /opt/myblog/db/blog.db < /path/to/migration.sql
# 手动记录
sqlite3 /opt/myblog/db/blog.db "INSERT INTO _migration_history (script_name, executed_at) VALUES ('xxx.sql', datetime('now'));"
```

### 4.3 查看已执行

```bash
sqlite3 /opt/myblog/db/blog.db "SELECT script_name, executed_at FROM _migration_history ORDER BY executed_at DESC;"
```

## 7. 数据备份与恢复

### 7.1 备份

```bash
BACKUP_ENCRYPTION_PASSWORD=xxx \
BACKUP_GITHUB_TOKEN=ghp_xxx \
GITHUB_BACKUP_REPO=owner/my-blog-backup \
bash /opt/myblog/scripts/blog-backup.sh
```

### 7.2 应急恢复

```bash
sudo systemctl stop myblog
ls -lt /opt/myblog/db/backups/ | head -5
sudo cp /opt/myblog/db/backups/blog-YYYYMMDD-HHMMSS.db /opt/myblog/db/blog.db
sudo chown myblog:myblog /opt/myblog/db/blog.db
sudo systemctl start myblog
```

## 9. 故障排查

| 症状 | 第一步 |
|---|---|
| 80 端口连不上 / 502 | `journalctl -u myblog -n 100` |
| `Could not resolve placeholder` | 检查 `/etc/myblog/myblog.env` |
| 升级后 401 | 检查 `JWT_SECRET` 是否被改 |
| SQLite locked | 检查 WAL 模式 |
| 跨域报错 | 检查 `CORS_ORIGINS` |
| 增量 SQL 失败 | 看脚本输出的失败文件名 |
| 前端新文章没出现 | `bash scripts/rebuild-static.sh` |
