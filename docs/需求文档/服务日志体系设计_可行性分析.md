# 《服务日志体系设计》（REQ-LOG-2026-06-18）可行性分析

分析日期：2026-06-18
分析方式：对照需求文档与代码库实际现状逐条核实（AGENTS.md、pom.xml、各模块源码、application 配置、deploy-server.sh、前端 composables）

## 结论

整体可行，无架构性阻碍。技术栈（SLF4J + Logback，Spring Boot 2.7.18 默认依赖）原生支持滚动、异步、MDC traceId，不需要引入新依赖，与 Java 1.8 的环境约束（AGENTS.md §4.1）不冲突。文档对现状的描述基本准确，但有一处描述性错误，部署脚本侧已先行实现了一部分需求。

## 现状核实结果

- **缺失项 A/B/C 属实**：项目确实没有 `logback-spring.xml`，仅靠 Spring Boot 默认控制台输出。`AdminAuthFilter`、`AuthController.login`、`DeviceService`、`JwtUtil` 四个鉴权核心类确认**完全无日志**，与文档"缺失项 B"描述一致。文档列出的 6 个已有 `@Slf4j` 的类（PageViewFilter、PageViewService、GlobalExceptionHandler、ApiWhitelistService、CommentController、SiteSettingsService）也全部核实存在。
- **FR-5.5 的前提属实**：全代码库搜索 `FilterRegistrationBean` 零匹配，现有 filter（如 `PageViewFilter`）都是 `@Component` + `@Order` 方式注册，新增 `TraceIdFilter` 用同样方式声明 `@Order(Ordered.HIGHEST_PRECEDENCE)` 可行，不需要改动现有 filter 注册方式。
- **部署脚本已部分先行落地**：`scripts/deploy-server.sh` 第 409-443 行已经实现了标注"REQ-LOG-2026-06-18"的 logrotate 配置，同时覆盖 Logback 文件（30 天）和 systemd 重定向的 app.log/app-error.log（7 天），与文档第 6 节、NFR-4 的描述完全一致。这部分不需要新工作，只需要核对 Logback 侧的文件名/路径与该脚本约定的路径匹配。
- **`BusinessException` 异常类确认存在**（blog-common，含 code 字段），FR-4.1 的分级处理有现成基础，`GlobalExceptionHandler` 已经按 BusinessException/未知异常分两级处理，只需补 traceId 字段。

## 发现的一处文档描述误差

文档 2.2 节"非目标"中写"慢 SQL 专项监控（MyBatis-Plus 自带 SQL 日志已开）"，但实际三个 profile 配置文件均将 `com.baomidou.mybatisplus` 设为 **WARN** 级，SQL 不会打印。该说法与实际配置不符。由于慢 SQL 监控本身在本期非目标范围内，这处误差不影响本期实施，但若未来要做慢 SQL 专项，需要先把日志级别调到 DEBUG，文档里这句话容易让人误以为"现成可用"，建议落地前修正措辞。

## 需要补充考虑的点

- **前端 X-Trace-Id 消费侧**：`useAdminApi.ts`/`usePublicApi.ts` 目前没有任何读取响应头 traceId 的逻辑，全局搜索 `traceId`/`X-Trace-Id` 零匹配。但 US-3 的验收方式是"用户从浏览器 devtools 复制 X-Trace-Id"，属于手动操作，不依赖前端代码改动，这是文档刻意选择的轻量方案，逻辑自洽，不算缺口。
- **改动面**：落地时至少涉及新增 `logback-spring.xml`、新增 `TraceIdFilter`，以及给 `AdminAuthFilter`、`AuthController`、`DeviceService`、`JwtUtil` 四个类补齐日志语句，外加 FR-3 涉及的文章/评论/上传/设置等多个 controller/service 的 INFO/WARN 埋点，改动文件数量中等（预估 10-15 个文件），均为新增日志语句，不改变业务逻辑，回归风险低。
- **NFR-1 的 P99 <1ms 验收**：依赖异步 appender（`neverBlock=true`），在单核 VPS 上是合理设计，但文档没有给出如何隔离测量"日志引入的延迟差异"与"其他因素噪声"的方法，验收标准（5.2 节"差异 < 5%"）在单机 1C2G 上可能受系统抖动影响，实测时建议多次取样。

## 风险条目复核

文档第 7 节列出的 6 条风险（磁盘写满、异步丢日志、traceId 异步线程丢失、高频路径日志爆炸、密码误打日志、部署未建目录）均对应了实际可执行的缓解措施，且都在 Logback 原生能力范围内（`SizeAndTimeBasedRollingPolicy`、`totalSizeCap`、`neverBlock`），没有需要额外造轮子的部分，风险评估合理充分。

## 总体评价

需求边界清晰、非目标列得明确，验收标准可执行（curl 模拟、grep 校验都是确定性验证），决策记录完整可追溯。可行性高，建议落地前只需修正"MyBatis-Plus 日志已开"这一处描述，其余可直接进入设计/开发阶段。
