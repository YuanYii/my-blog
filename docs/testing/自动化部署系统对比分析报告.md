# 自动化部署系统对比分析报告

> 项目：my-blog（个人博客系统）
> 生成日期：2026-07-09
> 对比对象：自建部署系统 vs 标准 DevOps 平台

---

## 1. 系统架构对比

### 1.1 部署流程

| 环节 | my-blog 系统 | DevOps 平台（Jenkins/GitLab CI/GitHub Actions） |
|------|-------------|-----------------------------------------------|
| 触发方式 | 前端 UI 一键升级 | Web UI / Git Push / Webhook 触发 |
| 构建产物 | GitHub Release（jar + frontend-static.tar.gz） | Artifactory / Nexus 制品库 |
| 部署脚本 | `deploy-server.sh`（Shell 脚本） | CI/CD Pipeline（YAML 配置） |
| 版本来源 | GitHub Release Tag | Git Tag / 分支 |
| 执行位置 | 宿主机直接执行 | 容器/VM 隔离执行 |

### 1.2 核心组件映射

| my-blog 组件 | DevOps 平台对应 | 功能 |
|-------------|----------------|------|
| `upgrade-agent.py` | Jenkins Agent / GitLab Runner | 执行部署任务的工作节点 |
| `UpgradeController.java` | Jenkins API / GitLab API | 接收部署请求的控制层 |
| `upgrade.vue` | Jenkins Blue Ocean / GitLab Pipeline UI | 可视化操作界面 |
| `upgrade_record` 表 | Pipeline Execution History | 部署执行记录 |
| `deploy-server.sh` | Jenkinsfile / .gitlab-ci.yml | 构建部署脚本 |
| `publish-release.sh` | Build Artifact 阶段 | 打包发布产物 |
| `schema-sqlite.sql` | Flyway / Liquibase | 数据库迁移 |

## 4. 优势与不足

### 4.1 my-blog 系统优势

| 优势 | 说明 |
|------|------|
| 轻量级 | 无外部依赖（Jenkins/GitLab），纯 Shell + Python + Java |
| 一站式 | 版本管理 + 部署 + 日志 + 审计 全部自建 |
| 可定制 | 完全按项目需求定制，无平台限制 |
| 低成本 | 无需额外服务器资源 |
| 安全性 | 仅本地访问（127.0.0.1），外部无法触发 |

### 4.2 my-blog 系统不足

| 不足 | 说明 | 改进建议 |
|------|------|---------|
| 无环境隔离 | 直接在 prod 执行，无法在 staging 验证 | 增加 staging 环境 |
| 无自动回滚 | 升级失败需手动重新部署旧版本 | 增加自动回滚机制 |
| 无并行执行 | 单机串行，无法并行部署多个服务 | N/A（单机场景） |
| 无通知机制 | 升级完成后无通知 | 增加邮件/飞书通知 |
| 无审批流 | 仅手动确认，无多级审批 | 增加审批流（可选） |
| SSE 超时 | 长时间部署会断开连接 | 增加 reconcile 机制 |

### 4.3 DevOps 平台优势

| 优势 | 说明 |
|------|------|
| 环境隔离 | 多环境（dev/staging/prod）隔离部署 |
| 自动回滚 | 版本快照一键回滚 |
| 并行执行 | 多节点并行部署 |
| 通知集成 | 邮件/Slack/飞书通知 |
| 审批流 | 多级审批（Approve/Reject） |
| 可观测性 | 完整的监控和告警 |

---

## 5. 总结

my-blog 的自动化部署系统是一个**轻量级自建 CI/CD**，用 Python agent + Shell 脚本 + 前端 UI 实现了 DevOps 平台的核心能力：

- **版本管理**：GitHub Release API
- **自动部署**：deploy-server.sh + upgrade-agent
- **日志追踪**：SSE 流式 + upgrade_record 表
- **升级记录**：upgrade_record 表持久化

与标准 DevOps 平台相比，my-blog 系统更轻量、更定制化，适合个人博客这类单机部署场景。如果未来需要多环境部署或团队协作，可以考虑迁移到标准 DevOps 平台。
