# 生产环境升级问题记录

> 版本：v5.3.0+
> 日期：2026-07-09
> 环境：Ubuntu 生产服务器

---

## 问题清单

### 问题 1：upgrade-agent 未运行 → Connection refused

**现象**：点击"开始升级"报 `Connection refused`

**原因**：生产环境没有 supervisord，upgrade-agent 服务未安装

**解决**：
```bash
# 复制服务文件
sudo cp /opt/myblog/scripts/upgrade-agent.service /etc/systemd/system/

# 启动服务
sudo systemctl daemon-reload
sudo systemctl enable upgrade-agent
sudo systemctl start upgrade-agent

# 验证
sudo systemctl status upgrade-agent
curl -s http://127.0.0.1:28081/health
```

---

### 问题 2：GITHUB_TOKEN 未配置 → 版本列表为空

**现象**：`GET /admin/upgrade/versions` 返回空列表

**原因**：Java 进程环境变量中没有 `GITHUB_TOKEN`，无法访问 GitHub API

**解决**：在 `/opt/myblog/myblog.env` 中添加：
```bash
GITHUB_TOKEN=你的GitHub PAT
GITHUB_REPO=YuanYii/my-blog-prov
```

然后重启服务：
```bash
sudo systemctl restart myblog
```

---

### 问题 3：配置文件位置不统一

**现象**：GITHUB_TOKEN 配置在 `application.yml`，与现有 `myblog.env` 风格不一致

**原因**：新增功能时未遵循项目配置规范

**解决**：
- 统一迁移到 `/opt/myblog/myblog.env`
- 清理 `application.yml` 和 supervisord 中的重复配置
- `run-myblog.sh` 启动时 `source myblog.env`，环境变量自动注入 Java 进程

---

### 问题 4：upgrade-agent.service 未打包到 Release

**现象**：v5.3.3 Release 中没有 `upgrade-agent.py` 和 `upgrade-agent.service`

**原因**：`publish-release.sh` 未包含这两个文件

**解决**：修改 `publish-release.sh` 添加打包逻辑：
```bash
cp "$ROOT_DIR/scripts/upgrade-agent.py"     "$STAGE_DIR/assets/upgrade-agent.py"
cp "$ROOT_DIR/scripts/upgrade-agent.service" "$STAGE_DIR/assets/upgrade-agent.service"
```

---

### 问题 5：deploy-server.sh 缺少 LOCAL_SIM 模式安装逻辑

**现象**：LOCAL_SIM 模式下 deploy-server.sh 不会自动安装 upgrade-agent

**原因**：只在 systemd 路径添加了安装逻辑，supervisord 路径遗漏

**解决**：在 `deploy-server.sh` LOCAL_SIM 分支添加 supervisord 配置生成逻辑

---

### 问题 6：upgrade_record 表未创建

**现象**：v5.3.3 部署后 `upgrade_record` 表不存在

**原因**：full 模式下 DB 已存在时跳过 schema 执行，增量迁移未包含该表

**解决**：在 `deploy-server.sh` 增量迁移 section（约第 521 行后）添加：
```bash
if ! sqlite3 "$DB_FILE" "SELECT name FROM sqlite_master WHERE type='table' AND name='upgrade_record';" | grep -q upgrade_record; then
    sqlite3 "$DB_FILE" "CREATE TABLE IF NOT EXISTS upgrade_record (...);"
fi
```

---

### 问题 7：SSE 连接超时 → 记录卡在 RUNNING

**现象**：deploy-server.sh 执行时间过长，SSE 连接断开，`event: done` 未送达

**原因**：deploy 重启后端时 SSE 连接中断

**状态**：已知问题，需后续添加 reconcile 机制

---

### 问题 8：agent 未运行时升级报错格式异常

**现象**：`No converter for LinkedHashMap with text/event-stream`

**原因**：agent 连接失败抛异常，GlobalExceptionHandler 返回 Map，但响应类型已设为 SSE

**解决**：在 `UpgradeController.java` 中捕获 `ConnectException`，通过 SseEmitter 返回错误

---

### 问题 9：publish-release.sh 上传遗漏 upgrade-agent 文件

**现象**：v5.3.8 Release 的 SHA256SUMS 包含 upgrade-agent 哈希，但 assets 中没有文件

**原因**：打包阶段文件复制到了 staging 目录，但上传阶段 `upload_one` 列表漏了这两个文件

**解决**：在 `publish-release.sh` 的 `upload_one` 列表中添加：
```bash
upload_one "$STAGE_DIR/assets/upgrade-agent.py"        "upgrade-agent.py"
upload_one "$STAGE_DIR/assets/upgrade-agent.service"   "upgrade-agent.service"
```
